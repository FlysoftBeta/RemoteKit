# Android Chromium 软键盘与 IME

2026-11-05。对照 Chromium 157.0.8103.15 本地 checkout（基线 `1aa07b638799e59656559ae6c6649d4b197f555e`）、Chromium 89.0.4389.128 源码及官方文档。本文是源码调查，未运行实体 Android、Brave 138、Chrome 89 Android 或本地 GPU 实验。搜索框现象及已跑的 Viewer/Endpoint 复现见[本轮调查](keyboard-search-investigation-20261105.md)。

## 焦点、可编辑和系统键盘

- Blink 157 的 `Element::Focus` 先建立 DOM 焦点，随后仅在 frame 有 sticky user activation 时走该路径的键盘请求。一次可信手势后的异步 focus 有机会发起请求，即使 transient activation 已过。Android 的 `GestureTap` 另有 show 请求。Java 侧继续检查可编辑性、input mode 和宿主状态，调用 Android `showSoftInput`，再异步接收结果决定何时将编辑点滚入视野。Viewer 的 textarea `activeElement` 仅证实 DOM 聚焦，`focus({preventScroll:true})` 也不能保证 Android 后续没有 caret panning。[Blink Element::Focus](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/dom/element.cc#L8738-L8757) · [Android ImeAdapterImpl](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L938-L1022)
- Android 157 可编辑节点 ID 换代触发 `restartInput`，走正常分支时不请求 hide。type NONE 会请求 hide。已聚焦节点的 `inputmode` 改为 NONE 在没有硬件键盘时也会请求 hide，DOM 可编辑性仍由 type 判断。改回文本型会重新配置，但弹出仍看 show 请求。89 源码已有 mode NONE 隐藏、物理键盘例外和换可编辑节点时重启连接。Chromium 157 的输入模式专项测试在源码中标为 disabled，源码分支不能代替实测结果。[157 状态分支](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L774-L849) · [89 状态分支](https://github.com/chromium/chromium/blob/89.0.4389.128/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L424-L449) · [89 focusedNodeChanged](https://github.com/chromium/chromium/blob/89.0.4389.128/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L899-L909)
- Android Back 可只收起输入法。Chromium 正常 show 分支的注释明确考虑系统关闭后相同 type 仍需在合适请求上再次 show。Viewer 应允许 textarea 继续聚焦，观察到视口恢复只能更新键盘意图，不应据此结束候选或触发 blur。用户再次点击的重开路径应独立验证。[Android 输入法可见性](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility) · [157 状态分支](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L838-L849)

## 编辑事件

- Android 89 和 157 的常规 `setComposingText`、`commitText` 路径由 229 的 keydown/keyup 包围。157 原生测试对新候选断言 keydown(229) → compositionstart → compositionupdate → input → keyup(229)，单独调用 finish 时可以仅有 compositionend，直接 commit 则可以只有 keydown(229) → input → keyup(229)。这些测试未在本机运行，其日志断言没有记录 beforeinput。157 的 Gboard 物理键重放另有分支。不能要求每次 Android 编辑都带 compositionstart/end 或 229。[89 JNI 路径](https://github.com/chromium/chromium/blob/89.0.4389.128/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L781-L805) · [157 Android IME 测试](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/javatests/src/org/chromium/content/browser/input/ImeTest.java#L1588-L1628)
- Blink 157 实际执行先派发 compositionupdate，再派发 `beforeinput(insertCompositionText)`，应用编辑后派发 input。相邻源码注释与 UI Events 文档的前两项顺序相反。该 beforeinput 为 noncancelable，直接插入文本与组合编辑走不同路径。记录 `inputType`、`isComposing`、`cancelable`、`isTrusted` 和实际时间，可避免把跨版本的测试写成同一条总序。[Blink IME 派发](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/input_method_controller.cc#L387-L406) · [Blink InputEvent](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/events/input_event.cc#L103-L107) · [UI Events](https://www.w3.org/TR/uievents/#events-composition-input-events)
- Blink 一般在正常焦点更改时尝试 finish composition，若此时没有可派发的 focused element，结束事件直接跳过。Android Chromium 的 restart 测试也明确由 IMM/IME 决定是否调用 finish，不能只凭连接重启推断 DOM compositionend。Viewer 同一 textarea 保持聚焦而远端 owner 换代时，浏览器也不会因该 owner 变化自然 blur。旧候选需要隔离，即使稍后收到结束或对应的普通 input。[Blink 焦点变化](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/input_method_controller.cc#L1983-L1987) · [结束派发](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/input_method_controller.cc#L326-L339) · [Android restart 测试](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/javatests/src/org/chromium/content/browser/input/ImeTest.java#L1544-L1555)

## 视口与模拟边界

- Android Chrome 89 的历史默认行为同时缩小 layout 和 visual viewport。Chrome 108 起新版默认仅缩小 visual viewport，viewport meta 可显式选择两者一起缩小或覆盖内容。Viewer 没有显式设置该属性。CSSOM View 在同一轮 resize steps 先处理 Window，再处理 VisualViewport，offset 的变化通过独立 scroll 事件传递。Android show 后滚入 caret 的逻辑与高度变化异步，不应从一次 resize 事件推定所有几何已到齐。仅 offset 变化不要求重配远端。[Chrome Android 108 变更](https://developer.chrome.com/blog/viewport-resize-behavior/) · [CSSOM View 事件](https://drafts.csswg.org/cssom-view/#events)
- 候选栏显示、展开或隐藏可改变输入法实际占用高度。其轨迹因输入法和模式而异，尚无本次设备数据。全高回升后再降、宽度或 scale 改变、仅 offset 平移与软件键盘不改变视口（例如浮动键盘）都不能靠单一高度样本识别。当前几何规则只覆盖可见高度变化，单一固定高度的假键盘不能验证候选栏或 Android caret panning。
- Chrome 157 CDP 的 `Input.imeSetComposition` 与 `Input.insertText` 直接调用 renderer widget 的 IME 接口。由此可测试真实 Blink 编辑事件和 textarea 状态，但覆盖不到 Android InputConnection、229 外层键事件、键盘可见性、系统 Back、候选 UI 或其 insets 动画。移动模拟提供触摸、DPR、屏幕和媒体特征，脚本高度另算独立模拟。Chrome 89 CDP 源码有 `insertText`，没有 `imeSetComposition`。89 测试可用 CDP 补强直接文本路径，候选 start/update/end 如用脚本则单独标明为合成事件。[157 CDP 后端](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/browser/devtools/protocol/input_handler.cc#L1281-L1358) · [89 CDP 定义](https://github.com/chromium/chromium/blob/89.0.4389.128/third_party/blink/public/devtools_protocol/browser_protocol.pdl#L3494-L3501)

## 有限验证建议

1. 一组移动几何模拟。首次可信 tap 后按多步缩短 VV，候选栏先回升部分高度、保持超过 settle 窗口，再缩回，同时插入仅 offset 的 scroll。预期保持一次 textarea focus，部分回升无 dismissal，offset-only 不换远端尺寸。模拟 Back 只恢复高度，保持 activeElement 且无新 focus 循环，用户再次点击可重开。Chrome89/布局模式可只补一组 window 与 VV 高度一起变的用例。
2. 一组 Blink 候选及 owner 换代。157 用 CDP 先更新候选，在远端替换节点后结束旧候选，断言旧 commit 没有改动新目标，再开启新组合并只提交一次。独立确认无 composition 的直接文本提交。另有一个可单独测的缺口：当前 `EditingInput` 在换 owner 后保留 revokedComposition，直到新的 compositionstart、旧 compositionend 或 blur；若系统没有给 end 且下一笔是 Android 直接 commit，守卫会继续拒绝直接编辑，硬件键也会被 composing 守卫跳过。合成模型能证明该分支，实体输入法能否到达该序列仍未知。先取得序列证据，避免凭超时放行旧文本。
3. 一次实体设备短回归。记录浏览器/Android/IME 版本，分别首次打开 Google 二次搜索与哔哩哔哩顶部搜索，然后在其中一站验证一次候选确认、一次系统 Back 和重开。采集单调时间、focus 与 activation、Window/VV 高度和 offset、目标代次与编辑事件类型，候选内容只记录长度。若要核对系统实际显隐，可同步录屏或在可用的 Android 调试环境观测 IME insets。成功条件为一次用户意图对应一次开合，远端候选只落在有效目标，peer/track 不换代。此前 UD710/Brave 138 是另一批现场环境，本次设备仍待确认。

## 同焦点 textarea 能否显式取消旧候选

- `textarea.setSelectionRange` 更新 DOM selection，关闭 typing command 并明确保留焦点。它没有请求取消 composition 的调用。Chromium Android 的 selection-change 测试先等待新 selection 和仍在的旧 composition range，再由测试输入法模拟 finish。Browser 确实可经 TextInputState / `ThreadedInputConnection.updateSelection` 把新 selection 和 composition 范围通知 Android，但收到通知的 IME 可以有不同响应。[TextControlElement::SetSelectionRange](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/html/forms/text_control_element.cc#L629-L691) · [Android selection 测试](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/javatests/src/org/chromium/content/browser/input/ImeTest.java#L169-L187) · [Android 更新 selection](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/java/src/org/chromium/content/browser/input/ThreadedInputConnection.java#L213-L240)
- `textarea.value = sentinel` 在值相同时早退。值不同时，JS 路径以 `kDispatchNoEvent` 替换内层编辑器子节点。由源码推导，旧 composing range 的两个边界会被移到容器开头，折叠后 `HasComposition()` 变为 false。这个过程没有调用 Blink 的显式 cancel、发出 compositionend 或要求 Android 重启输入连接。渲染端随后可以报告已无 composing range，但旧 IME 回调仍可能送达。若下一条是旧候选的 commit，Blink 此时会走普通插入分支，进一步削弱新旧输入的可区分性。保持 quarantine 时不重置代理内容，比把赋值当作 owner 隔离更安全。[Textarea 赋值](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/html/forms/html_text_area_element.cc#L588-L648) · [替换编辑器子节点](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/html/forms/text_control_element.cc#L1107-L1133) · [Range 折叠](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/dom/range.cc#L1456-L1475) · [Composition 判断](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/input_method_controller.cc#L298-L301) · [Commit 分支](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/input_method_controller.cc#L625-L637)
- Android 有内部取消路径，最终调用 `restartInput`。EditContext 的 selection/text 写入触发这一取消行为，在该 157 基线上由 test 状态的特性控制，也没有 89 兼容路径。此次未找到对普通 textarea 可用、能保证旧 Android InputConnection 回调已隔离且保留键盘可见性的 JS 边界。[Android 内部取消](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/content/public/android/java/src/org/chromium/content/browser/input/ImeAdapterImpl.java#L2210-L2214) · [EditContext 取消](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/core/editing/ime/edit_context.cc#L234-L247) · [特性状态](https://github.com/chromium/chromium/blob/1aa07b638799e59656559ae6c6649d4b197f555e/third_party/blink/renderer/platform/runtime_enabled_features.json5#L2760-L2765)
- 可选的小型探针无需 RemoteKit 或 GPU。用 CDP 在独立 157 textarea 开始同一候选，分别跑仅移动 selection、修改值并移动 selection、blur 三个分支。记录操作后是否已有 end，以及下一条 CDP 更新是否有新 start、下一条 commit 是否表现为普通插入。该探针只能核对 Blink range 和 DOM 事件。Android 是否把旧候选当直接提交，需要实体 IME 或 Android instrumentation 检查。
