# 拍照与文件篮重设计（2026-11-04）

这是对用户否定的 162141 界面的替代设计，尚非实现或实机验收。只有**文件篮、拍照**两个主界面；拍下后立即占据篮子中的确定位置，后台处理，返回即见篮子，不再出现“检查照片”“加入文件篮”中转。相机连续拍摄默认开启。模式与连续拍摄开关在取景中可见、可改。最终仅“普通照片 / 文档扫描”两种模式；扫描合并文档矫正和保色增强，不设独立矫正模式、不提供或默认黑白二值化。

已核对 `photo-library-capture.tsx`、`file-chooser-dialog.tsx`、`basket-rows.tsx`、`file-card.tsx`、`my-files.tsx`，以及 `camera-capture.ts`、排序组件和 `docs/file-library-ux.md`。现实现的问题是：相机顶部表单和底栏占布局空间、video contain 进一步缩小；横屏仍用底部快门；全流程共用 busy 锁阻止连续拍摄；照片暂存独立 slots，再强制审阅、最后逐项导入。原 UX 文档的“拍照统一审阅”及 chooser 标题/底部栏布局由本设计取代，拖拽仲裁与服务端确认消费规则继续保持。此文只定义 UI 和可见行为，Control/Endpoint 状态、取消协议、裁剪数据契约由 root 集成确定。

## 全屏取景与操作

相机占满当前可用 visual viewport，黑底，video 绝对定位铺满，不放入 DialogContent、卡片或带 padding 的中间容器。不保留实体标题栏。所有控件浮在画面上，使用局部透明黑背景/短渐变确保对比度。页面不滚动，亦不触发远端 resize；相机退出后恢复原篮子的滚动和焦点。CSS 尺寸为逻辑 px。

| 区域 | 竖屏（可用宽 ≤ 高） | 横屏（可用宽 > 高） |
| --- | --- | --- |
| 返回 | 左上 44×44，距安全区边 8 | 左上同规格 |
| 切摄像头 | 右上 44×44，距安全区边 8 | 右上 44×44，归入右侧操作区 |
| 快门 | 底部中心，72×72，距底安全区 18 | **右侧垂直居中**，72×72，距右安全区 18 |
| 文件篮入口 | 快门左侧 48×48 最新缩略图＋数量角标 | 快门下方，48×48，间隔 24；高度不足时贴底安全区 12 |
| 连续拍摄开关 | 快门右侧 44×44 图标，带“连续”短标签/开关状态 | 快门上方，44×44，间隔 24 |
| 模式 | 快门上方单排 44 高分段：普通照片／文档扫描 | 下方靠左的同一单排，止于右操作区前 12 |

竖屏底部渐变区约 156 高＋安全区，横屏右侧渐变区约 108 宽＋安全区；它们只覆盖画面，不压缩 video。横屏下方模式距安全区 8，不能生成第二个整宽底栏。所有边距叠加 `env(safe-area-inset-*)`，左右安全区均处理，避免旋转后刘海盖住返回或快门。横屏可用高不足 320 时快门 64，切换/连续/篮子各 44，分布在右侧区内，不移回底部。模式行最多约 240 宽；极窄宽度短标签“照片／扫描”，可访问名称仍完整。

不显示“连续拍照”大标题、不常驻技术状态、分数、帧数或大完成按钮。篮子入口可访问名称为“返回文件篮，N 项”；返回箭头与篮子入口均结束相机并返回原位置。需要重拍时返回箭头名称为“取消重拍”，当前待替换项显示一条轻量“重拍第 N 项”浮层。错误使用画面上方不超过两行的就地提示；权限失败时保留退出和重试，不空转 spinner。

快门按下给予短描边/闪白反馈，最长 1 秒的采样阶段仅快门及相机/模式变更暂时禁用。模式变更在下一次快门生效，本次任务冻结所选模式、镜头、方向和取景变换。连续开关表示“完成一次快门采样后留在相机，可继续按快门”，不是自动无限触发快门。关闭后一次采样成功即返回篮子，后台处理照常继续；采样失败留在相机。重拍总是一次采样后返回目标项，与连续开关无关。

## 看见的画面与照片

默认取景 `object-fit: cover; object-position: 50% 50%`，满屏显示实际可拍范围；不能把 contain 的黑边版本放大一层后仍输出另一视野。当前不镜像前摄预览，以免文档文字与输出左右相反。若以后采用镜像自拍，预览、ROI 与输出方向必须作为同一明确契约变更。

对已按方向规范化的摄像头源 `Ws×Hs` 与取景窗口 `Wv×Hv`，cover 比例 `s=max(Wv/Ws,Hv/Hs)`；画面所见源矩形为 `cw=Wv/s, ch=Hv/s, cx=(Ws-cw)/2, cy=(Hs-ch)/2`。实际普通照片输出采用这个矩形，不将屏外源内容悄悄放进结果；最终像素边界取整规则由实现统一，预览用同一规则反算。浮动控件遮挡不进一步裁掉照片。采样一开始冻结本次几何；中途旋转应终止该次未完成采样并提示重新拍摄，不能混入不同视野帧。

文档扫描将几何矫正与保色扫描增强作为一个功能，可以在这个可见区域内再做文档透视矫正，缩略图显示最终输出；保留的“原图”指文档处理前、与取景对应的静态照片。传感器未裁切原件是否另留由 root 决定，不在 UI 假定。需要完整文档时用户移动手机使整页进入可见画面，不能后台用预览外内容补边。

本地 getUserMedia 预览可用 video 元素，原照片/采样源不得经 H264、VP8/VP9 等视频编码链再解码取图。静态图像编码与预览缩略图允许存在；数据通道、采样尺寸、帧传输、Endpoint 质量反馈由 root 与采集实现确定。单次快门**质量够用即停止采样**，采样时间硬上限 1 秒、最多 20 个不同源帧；不把 20 帧当固定目标，不重复抓同一帧凑数。1 秒上限只描述采样，不谎称网络/后处理必在 1 秒结束。Endpoint 未及时回质量反馈时到上限即停，取已得到的帧继续处理。

## 拍下即入篮与局部状态

每次快门采样成功立即生成稳定占位与缩略图，按快门顺序入篮；网络完成先后不能改变顺序。多次在某项后插入时使用推进的插入位置，保留连续照片顺序。采样与后台上传/评估/处理分离：上一项后台处理中，只要有容量即可再次拍摄。实现设有界队列与字节预算；满额仅快门显示“处理中，稍候再拍”，已有照片、退出与篮子仍可用，绝不在前端无界积攒 20 帧×多次拍摄。并发数和预算交由 root 定，不将具体值写成用户要求。

| 项状态 | 篮子显示 | 可操作行为 |
| --- | --- | --- |
| 传输/选片/处理 | 已抓到的缩略图、局部进度环，短文案“处理中” | 返回/继续添加；可请求移除；此项不可发送；不得锁住整个篮子 |
| 完成 | 最终缩略图，无完成仪式 | 正常发送、重排、重拍、查看、移除 |
| 确有不确定候选 | 缩略图＋“待选片”角标 | 点卡片打开同篮的候选展开区；确认前该项不可发送 |
| 文档处理失败/质量不足 | 原图缩略图＋短警示 | 查看、重拍、移除；明确“使用原图”后成为可发送项，不能静默冒充扫描成功 |
| 传输/处理错误 | 保留位置及缩略图、错误角标 | 重试同项、重拍、移除；其他完成项不受阻 |

多选网页仍使用全部篮子项，因此任何未就绪项使“发送全部”禁用，并用图标角标/提示说明“还有 N 项处理中/待选片”；不能悄悄跳过。单选仅依赖明确选中的那一项状态。不存在选片疑问时绝不要求确认。

重拍保留旧项与顺序，成功新结果就绪后原位替换；旧图可在篮中标“重拍处理中”。重拍失败、取消或镜头打开失败保留旧图。需要选候选的新结果也不抢先摧毁旧图；用户确认新图后再替换。移除处理中占位应取消或丢弃其后续结果，晚到结果不得复活。退出相机不等于丢弃已采样照片；仅终止当前未完成采样、关闭摄像头，已受理后台任务继续在篮中反馈。锁定/断线/授权换代如何暂停和恢复遵从 root 的任务契约，不通过重新打开相机自动重放未知操作。

候选仅在确实不确定时提供两张，在篮子当前项的同一展开区域内显示：contain 大预览＋紧凑候选缩略图＋“使用这张”，另有“重拍”“移除”。点击候选只切预览，不立即确认。关闭展开区保留待选片。选定后按此项冻结的模式继续文档处理；不会清空模式或让用户重新走审阅页。普通大图、候选和更多均为同一文件篮内可关闭的展开状态，不能叠加新的 Dialog；打开一种会关闭另一种，返回/Escape 先收起展开，再处理篮子退出。集成后候选/大图上限为 `min(560, 可用高度−16)`，锚定时还受真实可用空间限制；普通更多/来源保留360上限，紧凑态不因此增高。

## 足够小的文件篮

默认图片篮是**单条横向 strip＋右侧三枚竖排图标**，没有顶部“选择文件/文件篮”双标题、来源独占行、操作说明常驻行或底部确认栏。优先锚定可靠可见 input；空间不够或 anchor 失效则同一布局放在小 Dialog，不能退回巨大的上传管理面板。

紧凑态外宽建议 360–440，受可用宽限制为视口减 16；内边距 6，右侧工具区 44 宽，间隔 6，默认高约 152。右侧自上而下：发送（44）、添加（44）、更多（44），间隔 2；发送唯一强调色，所有按钮有 tooltip/aria-label。卡片宽 96、高 124（预览 92＋文字区 32），间隔 6；contain 保留文档边缘，文件名一行、状态/大小一行，各 12px 左右。320 宽下仍有两张完整卡片与下一张边缘。排序容器不能继续硬编码 144 宽，须传紧凑尺寸；我的文件网格保留较大卡片，不全局缩小。

单选 Radio 仍有 44 触控命中区，在缩略图右上独立于整卡按钮，不用缩小实际可点击面积换紧凑。序号放左上。单选点击图片开菜单，Radio 选择文件，两者不混同；多选发送图标标数量，工具提示“按顺序发送全部 N 项”。无项时 strip 区写“添加文件”，发送禁用，添加可用。不每张图永久显示重拍/处理按钮。

“添加”替换式展开设备文件、拍照、我的文件三个来源菜单；选拍照直接进入全屏相机，底层篮子 inert/不重复可访问。插入操作沿用项菜单“在后面插入”，转到同一来源菜单，不叠两层菜单。摄像头返回原篮子，保持新增项可见。

“更多”在同一容器展开一块紧凑面板，包含视图切换图标按钮、来源域名与文件限制/单选说明、关闭选择；需要分组选择时也使用此处的内联选择状态与确认，不能再盖 GroupPicker。展开高度按内容，最大 `min(360, 可用高度−16)`；只有内部区域滚动。来源与页面身份必须可发现，完整域名在更多可读；紧凑态以来源 icon 的可访问说明关联，避免长 URL 重新吃掉一整行。关闭/取消仍执行原网页请求取消语义，不等同移除篮子内容。

普通文件至少 3 个且占比 ≥2/3 时沿用列表默认；手动切换后实例内保持。列表是同一个篮子的列表态，不挤进 124 高图片条：每行最低 56，最多约 3 行可见后局部纵滚，左手柄 44、文件名、行内直接操作按钮；右侧三按钮不动。窄宽下操作可用带 tooltip 的紧凑 icon，不转为必须先开行菜单。图片卡片整卡鼠标拖动、触屏横滑/200ms 长按拖动、点击才开菜单；保留现有 revision 冲突回滚、键盘排序和拖后 click 抑制。后台结果更新不得在拖动中突然替换集合结构；冲突按权威状态结束当前拖动。

“我的文件”仍是独立 tab、按日期分组展示，不变成第三个拍照主界面。其篮子入口复用上述同一篮子。直接拍到档案时，有分组必须在开始此次添加前明确选分组或未分组，使用来源展开区内联选择；拍摄后的后台项展示在当前目的地，退出直接回原 tab，不生成检查照片页。文件篮与档案删除语义保持区分。

## 实施与验收界限

`PhotoCapture` 只保留相机与采样控制，移除独立 review/candidate Dialog 与“最后保存 slots”阶段；篮子任务状态和候选操作集成入口由 root 定。`FileChooserDialog` 改为 strip 工具区布局并承接内联展开；`BasketRows`/`FileCard`/排序容器增加紧凑展示能力，保持档案大卡；`MyFiles` 复用同一相机退出路径与篮子，不新增特殊审阅分支。不要用全局 busy 统锁所有独立照片任务。

必要视觉尺寸：390×844、844×390、320×568、568×320、桌面 1280×720；横屏快门实际位于右中，取景覆盖屏幕且 UI 不缩小 video；模拟左右刘海/底部安全区；Chrome89 不依赖 dvh、container query 或新 CSS 才能布局。几何用四边可识别标记验证取景与普通输出一致，旋转中采样不能混视野。动作组覆盖连续三拍（前项慢处理）、关闭连续、队列满退出、取消重拍保旧图、候选仅不确定时出现、候选在篮内确认、处理中移除晚到不复活、单/多选发送门禁、窄条横滑与拖动、普通文件列表及切换。合成源验证布局/状态，不代替实体手机手持可达性与实际摄像头质量。
