# UD710后续实验：音频隔离与QSV帧大小能力

2026-11-04本地完成四个串行70秒刺激场景，各自从设置开始诊断、悬浮按钮停止并完成tar.zst核验；媒体身份保持。没有并行benchmark、上传或构建。运行条件见[准备记录](ud710-av-experiment-20261104.md)。本轮没有新增生产码控修改或新的安装包上传。

## 音频结果

第一对按有音频→无音频运行，使用带CRC16和VideoFrame时间戳核对的读回；第二对因首对接收差异及较低提交FPS，按无音频→有音频反序复核，保持同一CRC图案，但不读取像素。反序组只讨论接收时序，不生成marker延迟。

| 探针 / 音频 | 首段末包→提交p95 | 第二段末包→提交p95 | 首段发送等待均值 | 第二段发送等待均值 | 首段 / 第二段提交FPS |
| --- | ---: | ---: | ---: | ---: | ---: |
| CRC读回 / 有 | 270.2ms | 89.7ms | 49.7ms | 15.7ms | 22.26 / 21.67 |
| CRC读回 / 无 | 44.6ms | 44.4ms | 47.3ms | 17.0ms | 26.18 / 25.90 |
| 仅元数据 / 无 | 44.0ms | 48.3ms | 47.8ms | 16.1ms | 25.69 / 26.61 |
| 仅元数据 / 有 | 50.2ms | 60.8ms | 47.5ms | 20.2ms | 25.44 / 24.36 |

首对实际视频缓冲窗口均值p95，有音频243.3/73.6ms，无音频24.2/41.2ms；反序组有音频22.7/46.0ms，无音频25.9/18.0ms。纯解码p95约0.6–1.0ms，组帧窗口均值p95约16–38ms。源节拍相近，RTT仍有差异：首对有音频首段p95 55ms、无音频31ms；反序分别24/38ms。因此不能将每个差异都归于音频。

**判定：首对音频条件相关的额外接收等待有迹象，但反序未复现270ms高等待，不能认定音频为唯一根因，也不能据此删除产品音频或默认取消同步。** 关闭音频没有消除发送排队。顺序和读回模式在两对之间同时改变，不能用跨对差值单独估计读回的因果影响；每对内部的音频条件对照仍可单独观察。

有音频组的发送/接收RTP均存在（首对3787/3749包，反序3779/3797包；不同端最后采样时刻不同，不能用这两个累计值计算丢包）。无音频组协商inactive，发送及接收音频项均缺席、包/字节均为0，视频统计正常。此处音频是该无声fixture的Opus静音载荷，不是有声视频的听感/口型同步验收。

首对marker分别146/146、150/150通过魔数、CRC和快照时间核对，无拒绝；读回p95约5.7–7.1ms。页面marker到提交p95分别392/216ms与321/215ms，仍非输入到物理scanout。两组无读回控制确认attempted=0。

## 为什么提交FPS低于先前本地组

四组Viewer反馈的RAF估计均约31.95–32.05Hz，先前`ud710-lag-cadence`约53–54Hz。与此同时本轮WebRTC观测输入58–59FPS，源间隔约16–18ms，首段解码约54.2–56.8FPS；旧组解码约55.8FPS。低提交FPS有共同的Viewer刷新节拍变化，不能直接算作本次编码回退。关闭像素读回也未恢复旧提交FPS。尚未确认RAF变化的操作系统/浏览器原因，没有把估计RAF称为物理屏幕刷新率，也没有变更用户显示或RDP设置。

## QSV单帧预算探测

新增显式目标`endpoint_qsv_frame_budget_probe`（默认不构建、不链接进服务）。同一Intel LUID 0:59951、device39877，D3D11硬件session，运行API1.35，1936×816、VBR、18/48Mbps、LowPower实际OFF。仅Query→Init→GetVideoParam，不编码帧，所以不证明AU大小、质量或时延。

| 名义FPS | I/P上限请求 | LowDelayBRC | Query状态 | Init/读回 | 实际I/P上限 |
| --- | --- | --- | ---: | --- | --- |
| 60 | 无 | OFF | 0 | 0 / 0 | 0 / 0 |
| 60 | 150000 / 100000字节 | OFF | 0 | 0 / 0 | 保留请求 |
| 60 | 150000 / 100000字节 | ON | 0 | 0 / 0 | 保留请求 |
| 2 | 150000 / 100000字节 | OFF | 5 | 0 / 0 | 0 / 0 |
| 2 | 无 | ON | 0 | 0 / 0 | 0 / 0（符合请求） |
| 2 | 150000 / 100000字节 | ON | 5 | 0 / 0 | 0 / 0 |

低FPS组合会被驱动清除大小限制，不能用非负返回值假装限制已生效；并非单独LowDelayBRC无法开启。当前固定上限候选没有通过低FPS门槛，没有进入生产。下一候选必须明确可用帧率/码率范围及低FPS处理，然后测实际AU分布和2/15Hz画质，不能把帧大小读回当成优化完成。
