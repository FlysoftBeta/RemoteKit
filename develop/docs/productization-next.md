# 当前性能优化之后的产品化任务

本文件记录用户新增要求，尚未实施。先继续现有优化与实播计划，主Agent认为当前改动已基本充分后自动接手本清单，不因新增任务中断正在进行的实验。当前固定分辨率控制变量实验不启用自动降分辨率。

## 自适应质量与配置收束

- 延迟超过300ms时自动降分辨率；相应换算Browser DPR。按Client Scale计算，默认Viewer DPR，允许override。实现时需明确各像素空间与输入坐标关系，保持可观测的实际尺寸。
- 用户质量偏好仅“优先高画质 / 自动 / 优先流畅”，共同控制分辨率、码率与目标帧数。移除其它用户可见质量preset及调参选项。
- 保留配置下发式自动化实验。专用测试页不需要交互控件；测试配置及固定变量不混入Viewer自动策略。
- 审查并移除无效实验开关，Hybrid/VDEnc混跑可移除；对未来常规控制变量实验确有价值的保留。历史开关、结论统一封存在单一文档，移除其它活跃文档的散落引用。归档不等于删除正式GPU/延迟Profiler。
- 将现有逐环节GPU与延迟计时、资源归因、完整metrics收集/重组设施工程化，能持续支持后续改动验证。

## 控制平面与Viewer

- 产品定位已超出demo；去除不必要UI，必要时重新设计交互。UI设计使用用户指定Astra 6 Medium，视觉验证使用Sol 6.1。
- 使用MUI构建浏览器外壳，沉浸式，不加无意义边框；内容区域随实际可用空间自动适配。
- 更多（三点）→设置统一管理设置。
- 平板模拟只做每站点UA模拟，在更多菜单设置；不模拟平板viewport。现有设备模拟设置与产品数据需迁移/兼容处理，避免混淆新旧含义。
- split window为类似Android多个应用side-by-side的多窗口体验，不能只把它理解为当前单窗口双tab拼接。
- 修复新窗口创建；明确新窗口、tab、站点设置及焦点/输入的关系，并实际验证。
- Viewer与Control使用WebSocket连接；WebRTC仍是Client直连Endpoint的媒体/输入链路，由Control鉴权管理。
- 简易多用户，客户端仅持有用户token，不保存任何设置。用户偏好、站点UA、Client Scale override及窗口状态等由Control托管。

## 可见性与memory saver

- 启用memory saver，由Control实现算法和产品层决策。
- Viewer断开后，Control将Endpoint对应可见性设为false，作为进入memory saver的条件。
- WebRTC连接状态单独决定渲染出帧与编码。不能把Control在线、Endpoint可见性、媒体连接三个状态混成一个开关。
- 浏览器恢复信息继续由Endpoint Session/Browser拥有；Control持有产品状态和有限对象引用，故障时重建并清理orphan。

实现前由主Agent固定状态机、用户/Session隔离及接口，然后按文件归属委派。先完成可审阅实现、必要迁移与自动化/视觉验证，再由主Agent提交推送。以上条目不能仅以设计文档或设置占位符视为完成。
