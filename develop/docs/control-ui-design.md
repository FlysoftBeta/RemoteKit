# RemoteKit Viewer 产品界面设计

日期：2026-11-01。设计交付，供本轮产品化实现使用；不是已实现能力清单。后端模型、协议与算法以主 Agent 固定的接口为准。

## 1. 页面就是工作区

打开 Viewer 并登录后，直接进入上次的浏览器窗口。每个窗口都有自己的标签栏、地址栏和页面；多个窗口可以并排使用。去掉现有品牌大头、WORKSPACE 标题、DEMO/Tenant 标签、底部状态栏和页脚，页面内容贴边占满余下空间。

用户不需要手动“连接 Endpoint”。登录成功自动连接，正常连接时不常驻绿色状态文案。只有连接变化、恢复或动作失败时，才出现相关提示。

固定的产品关系：一个用户拥有自己的 workspace 与 Endpoint Session；workspace 包含多个 Window；每个 Window 拥有自己的 tabs 和 activeTab。窗口并排是多个浏览器窗口共同可见，不是一个窗口同时选择两个标签页。

本设计保留 Chrome 89 客户端。MUI 版本由实现决定，不要求依赖 container query、`:has()`、`dvh`、Popover API 或 View Transition API。

## 2. 布局与密度

桌面单窗口：

```text
┌ [站点 A        ×] [站点 B      ×]  ＋             窗口 ▾ ┐
│ ←  →  ↻   [ example.com/path                         ] ⋮ │
├─────────────────────────────────────────────────────────┤
│                                                         │
│                    远程页面内容                          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

桌面并排：

```text
┌ [A ×] [B ×] ＋      窗口 ▾ ┐ ┌ [C ×] ＋         窗口 ▾ ┐
│ ← → ↻ [example.com]     ⋮ │ │ ← → ↻ [other.com]       ⋮ │
├───────────────────────────┤ ├───────────────────────────┤
│                           │ │                           │
│          页面 A           ┆ │          页面 C           │
│                           │ │                           │
└───────────────────────────┘ └───────────────────────────┘
```

两个窗口之间只有 6px 分隔拖动区；不套卡片、外边距、阴影或圆角。单窗口也不留下分隔区。页面本身不显示标题条、DIP 尺寸、点阵背景、设备外壳。

| 场景 | 外壳与窗口布局 |
|---|---|
| 指针精细、窗口宽 ≥600px | 标签行 36px，工具行 44px；图标按钮可见尺寸 32px，点击区至少 36px |
| 粗指针/触屏 | 标签行 44px，工具行 48px；图标点击区至少 44px |
| workspace 可同时容纳每窗 ≥360px | 按保存的窗口排列与比例并排展示；初次两窗各半 |
| 宽度不足以容纳所有并排窗口 | 聚焦窗口占满；窗口切换器显示“窗口 2 / 3”，其余窗口保留全部标签 |
| 极窄窗口 | 标签行保留当前标签与“标签页数量”按钮，点开列表；前进收进更多，后退/刷新/地址/更多仍直接可用 |

360px 是外壳可用性下限，不是远程网站的固定 viewport。不要为了保持并排让窗口横向溢出屏幕，也不要把多个完整页面纵向堆成很长的网页。变窄时只改变可见窗口集合，不合并 Window、不移动 tabs；恢复宽度时回到保存的并排关系。

外层用 `height: 100%` 的 flex 容器，所有中间容器设 `min-width: 0; min-height: 0`，页面容器占满剩余高度。用实际容器测量驱动 viewport。触屏键盘导致可用高度变化时，同样更新可见区；`visualViewport` 可用时辅助测量，普通 resize 保留回退。外壳不设 570px 等固定最小高度。

## 3. Window、标签与焦点

**窗口切换器**放在每窗标签栏右侧，显示窗口图标；有多窗时附数量。点击打开菜单，按排列顺序列出各窗口的活动页面标题，当前窗口打勾。每个项目有“切换到窗口”的可访问名称。

窗口菜单底部提供“新建窗口”和“并排显示 / 只显示此窗口”。更多菜单也保留“新建窗口”，用于熟悉浏览器菜单的用户。新窗口首先创建独立空白 tab；成功后聚焦其地址栏。空间允许时并排加入；空间不足时切换到新窗口。创建失败保留原窗口，并给“未能新建窗口 · 重试”。创建中不显示可以输入但没有服务端身份的假窗口。

点击其他窗口的外壳只改变当前操作窗口；点击远程页面才把键盘焦点交给该页面。鼠标经过另一窗口不抢焦点。活动窗口使用地址栏轻微强调和标签选中样式，不给整块页面画蓝框。

每个窗口独立维护地址输入草稿。状态刷新不覆盖用户正在编辑的地址。提交后显示导航进度，收到实际 URL 再替换；取消编辑恢复该窗口当前 URL。`Ctrl/Cmd+L` 指向当前操作窗口。其他浏览器快捷键仅在宿主允许拦截时补充，所有功能都有可点击入口，不把宿主保留快捷键当作唯一入口。

标签栏采用横向滚动；选中标签自动滚入视野。标签显示 favicon/通用站点图标、标题、关闭按钮；加载中用小型进度标记，页面休眠时使用低强调图标与 tooltip。标题截断，不挤掉关闭和新建按钮。键盘选择采用 roving tab index，左右键切换焦点、Enter 激活；关闭按钮是独立按钮，不能嵌套在另一个 button 内。

标签的更多操作通过右键和可见菜单入口共同提供：“在新窗口打开”“移到窗口…”。移动是转移同一标签的归属，保留页面状态；若本轮接口不提供移动，先只实现“在新窗口打开”并明确其创建新页面的行为，不做看似移动的复制。拖拽不是本轮必要前置条件。

关闭最后一个标签后，该窗口显示极简空状态：“打开一个网页”，地址输入与“新建标签页”入口仍在。关闭窗口是独立命令，避免用户关闭一个标签就失去整个工作位置。最后一个窗口可关闭为 workspace 空状态，中央提供“新建窗口”。

有 beforeunload 确认时，对话框标题“离开此页面？”，说明“此页面可能有未保存的内容”，动作“保留页面 / 离开”。取消后完整保留原窗口、标签和焦点。关闭整个窗口时仅在其标签全部真正关闭后移除窗口；中途取消就保留尚未关闭的部分，不预先从界面删去。

打开菜单/设置时结束远程按键与指针捕获，IME 按既有输入协议正确收尾。对话框关闭后回到触发按钮，不能自动向远程页面注入点击；用户再次点击内容时恢复页面输入。

## 4. 更多菜单

每个窗口地址栏最右端保留竖向三点，菜单根据该窗口的活动标签执行命令。

| 分组 | 菜单项与行为 |
|---|---|
| 浏览 | 新建标签页、新建窗口；窄窗收纳的前进 |
| 窗口 | 并排显示 / 只显示此窗口；关闭此窗口 |
| 当前站点 | “使用平板版网站”开关，下一行显示当前 hostname；仅 HTTP(S) 站点可用 |
| 全局 | 设置 |
| 账户 | 当前用户名；退出登录 |

站点开关只改变该站点 UA/Client Hints 策略，不改变 viewport、屏幕宽高、DPR 或画面的圆角。域名匹配范围由主 Agent 的站点键规则决定；菜单中始终显示实际受影响的站点名，不模糊宣传为“所有子域”。同一站点在其他标签中使用一致的保存偏好。

切换后保存到 Control，当前页面刷新以应用。请求尚未成功时开关显示保存中；失败回到原值并显示“站点设置未保存”。若页面要求离开确认，走已有确认流程；若取消刷新，提示“设置已保存，下次加载生效”，不假装当前页面已经切换。其他同站点标签不突然强制刷新，下一次加载采用新设置。

`about:blank` 等页面显示禁用状态和“打开网站后可设置”。不恢复旧的全局“桌面/平板”模式按钮、设备预设或旋转按钮。

## 5. 设置

唯一入口为“更多 → 设置”。桌面使用居中的 MUI Dialog，宽约 520px，最大高度为窗口高度减 48px；触屏窄屏使用 fullScreen Dialog。设置覆盖在 Viewer 上，不推挤页面或触发所有网页改尺寸。标题“设置”，右上关闭；内容简短，无左侧多级导航。

| 设置 | 控件与文案 |
|---|---|
| 画面质量 | 垂直 RadioGroup：**优先高画质**“尽量保留画面细节”；**自动**“平衡清晰度与响应速度”；**优先流畅**“优先保持操作顺畅”。默认自动。整个选项行可点 |
| Client Scale | 主标签“显示像素比例”，辅助标注“Client Scale”。Switch/Checkbox“跟随此设备”，默认开启；旁边只读显示实际 Viewer DPR，如“当前 1.5×”。关闭后出现一个数值输入和“应用”按钮；允许范围使用服务端返回约束，不在设计中另定 |
| 内存节省 | Switch，默认开启。说明“暂不使用的页面可以休眠，返回时自动恢复。”不暴露休眠秒数、引擎参数或回收算法 |
| 账户 | 只读用户名，“退出登录”文字按钮 |

质量与内存开关即时保存；输入型比例在“应用”后保存。每一项独立显示短暂“已保存”或内联错误，不为每次切换弹 toast，也不全局锁住所有操作。服务端确认为最终值；保存失败保留可重试的草稿，不能显示已生效。若关闭设置时比例草稿未应用，直接丢弃草稿；字段旁预先说明“点击应用后生效”。

显示像素比例控制采样清晰度，不作为网页缩放控件。改变后页面仍填满原可用内容区域；内部 Browser DPR 与编码分辨率换算由既定策略处理。三个质量模式统一调整分辨率、码率、帧率；正常设置不出现三个独立滑块，不暴露编码器、TU、LowPower、接收路径、marker 或播放延迟。

自动降低分辨率通常静默完成。持续影响操作时可出现一次简短提示“连接较慢，已调整画面质量”，无需弹出确认，也不反复跳出。精确尺寸和调整原因到独立诊断查看。

客户端不把质量、比例、站点 UA、窗口状态存入 localStorage、sessionStorage、IndexedDB 或偏好 cookie。持久化只保存用户 token；未提交的输入草稿与打开菜单状态留在内存。初次加载显示骨架/连接状态，收到 Control 偏好后再应用，不闪现旧设备设置。

## 6. 登录、创建与退出

登录页使用同一浅色基底，居中约 360px 的简洁表单，不加巨大营销图或仪表盘。标题“登录 RemoteKit”，字段与鉴权方案一致；若采用用户名/密码，标签为“用户名”“密码”，主按钮“登录”，次入口“创建账户”。创建页重复同样结构，标题“创建账户”，成功即进入自己的空 workspace。不开列用户列表，不展示其他用户 Session/Tenant。

首次进入空 workspace 自动准备第一个窗口或提供“新建窗口”，由 API 的创建时机决定；不要在渲染重试时重复创建。等待中给“正在准备浏览器…”，失败给一次明确重试入口。

退出登录立即遮去旧页面像素、断开本客户端媒体/控制连接并清除 token，回到登录页。关闭连接不等于删除用户窗口和标签，重新登录从 Control 读取。错误页/加载骨架不能短暂复现上一用户的画面或地址。token 过期提示“登录已过期，请重新登录”，不让用户反复点击无效的连接按钮。

## 7. 连接、恢复与节省内存

UI 分开接收控制状态、媒体状态、页面恢复状态；用户看到与当前影响相符的一句话。不要把“WebSocket 在线”展示成“画面已连接”。

| 状态 | 展示与操作 |
|---|---|
| 初次连接 | 内容区轻量加载态“正在连接浏览器…”；已有外壳来自 Control 状态 |
| 控制暂断、媒体仍正常 | 外壳下方一条紧凑提示“正在恢复连接…”；已有画面继续，控制命令暂停；是否继续远程输入依已确认授权/布局有效性决定 |
| 媒体断开 | 保留最后一帧并覆盖“画面连接中断，正在重连…”；停止向旧画面发输入。不要让静止视频看起来仍可操作 |
| Endpoint/Browser 恢复 | 同一窗口内显示“正在恢复页面…”；标签与 URL 保留。出现与当前身份、布局一致的新画面后解除遮罩 |
| 自动重试耗尽 | “暂时无法连接”与“重试”；细节可展开，不直接把 JSON/栈贴到页面 |
| 休眠标签被激活 | 标签立即选中，内容显示“正在恢复页面…”；恢复成功后操作，不因等待重复创建 WebView |
| 页面恢复失败 | 此页显示“页面未能恢复”与“重新加载”；其他窗口继续工作 |

短暂状态变化不弹模态框；连接提示可以用细条和内容 overlay，真正改变可用区域的常驻提示纳入内容测量。恢复后移除提示，不以“已重新连接”永久占一行。

用户离开 Viewer 后由 Control 处理不可见与 memory saver；UI 不显示“必须一直保持连接才能保留标签”。媒体链路决定是否持续渲染编码，控制在线与页面可见性不互相冒充。Control 只显示恢复结果，浏览器历史、表单等恢复资料仍由 Endpoint/Browser 托管。

## 8. MUI 组件与视觉 tokens

默认浅色，柔和灰色浏览器外壳、白色内容；品牌色只用于选中、焦点和主要动作。不新增主题切换偏好。

| Token | 建议值 |
|---|---|
| `palette.background.default` / `paper` | `#F2F4F7` / `#FFFFFF` |
| `palette.text.primary` / `secondary` | `#1F2937` / `#5F6B7A` |
| `palette.primary.main` / 强调背景 | `#245DB5` / `#E8EFFB` |
| divider / hover | `#DDE2E8` / `#E8ECF1` |
| error / warning / success | `#B3261E` / `#8B5700` / `#246C4A` |
| 字体 | `Segoe UI, Microsoft YaHei, sans-serif`；正文 14px、菜单 14px、标签 13px、Dialog 标题 20px；不下载外部字体 |
| 间距 | 4px 基数；工具行左右 8px，字段间 16px，Dialog 内边距 24px（窄屏 16px） |
| 圆角 | 地址栏 8px、菜单 10px、Dialog 12px；窗口与远程内容 0 |
| 阴影 | 仅 Menu/Dialog 使用低层级阴影；常驻外壳 elevation 0 |
| 焦点 | 2px primary outline；不依赖颜色单独表达连接错误或选中状态 |
| 动效 | hover 100–150ms；Dialog 150ms；不对远程 canvas 缩放/几何更新做 CSS 动画；遵循 reduced-motion |

以 `ThemeProvider + CssBaseline` 统一基础风格；外壳 `Box`，工具栏 `Toolbar`，动作 `IconButton + Tooltip`，地址栏 `InputBase`，菜单 `Menu/MenuItem`，设置 `Dialog/RadioGroup/FormControlLabel/Switch/TextField`，错误 `Alert`，少量结果 `Snackbar`，加载 `CircularProgress`。不为已有语义组件再包一层同样的卡片。

可用 MUI Tabs 的键盘/滚动机制，但带关闭按钮的标签必须检查最终 DOM，不嵌套 button；必要时做小型语义 TabStrip。图标使用一致的 MUI 图标集，尺寸 18–20px；所有图标按钮有明确 aria-label，Tooltip 不是唯一名称。状态文本用 `aria-live="polite"`，失败阻断才用 alert。

Chrome 89 样式以 flex/grid、普通 media query、ResizeObserver 为主；触屏判断不只根据宽度，可用 pointer media query。项目现有 `aspect-ratio` 等样式要有固定容器尺寸路径，避免依赖新浏览器布局特性。MUI 版本、构建目标与 polyfill 由实现验证。

## 9. 可实施组件边界

| 组件/模块 | 职责 |
|---|---|
| `App` / `AuthGate` | token 生命周期、登录门禁、用户切换清理；不直接实现远程输入 |
| `SignInView` / `CreateAccountView` | 登录/创建表单、字段错误、提交状态 |
| `WorkspaceShell` | Control 快照、可见窗口集合、聚焦窗口、响应布局 |
| `WindowFrame` | 单窗标签栏、地址栏、更多菜单、活动页面；props 绑定明确 windowId |
| `TabStrip` / `TabListMenu` | 标签选择/关闭/溢出，独立 pending 状态 |
| `NavigationBar` | 单窗地址草稿、导航、加载/停止、菜单入口 |
| `WindowSwitcher` / `WindowDivider` | 窗口切换、并排入口、比例调整；分隔条提供键盘方向键调整 |
| `RemoteViewport` | 实际内容测量、canvas 注册、呈现代次、坐标/输入/IME；保留现有输入与 transport 能力 |
| `ConnectionNotice` / `PageRecoveryState` | 根据不同连接与页面状态显示提示；不自行推导 Session 生命周期 |
| `MoreMenu` / `SettingsDialog` | 站点动作和全局偏好；通过 Control 命令保存 |
| `CloseConfirmationDialog` | 页面离开确认，携带明确的 tab/window 和 request identity |
| Control 状态 adapter | WS 快照/变更/命令结果；对外给 typed view model，隔离服务端字段变化 |

组件不另建一套永久产品状态。命令中明确 windowId/tabId；服务端快照决定 tabs 和窗口身份，组件只维护输入草稿、菜单锚点、拖动中的比例等瞬时状态。局部动作只禁用对应控件，避免当前单一 `pending` 让另一窗口也完全不可操作。

现有 `main.tsx` 的 `Viewport` 输入逻辑与 transport 连接边界适合保留后搬迁；`ControlState.tabs/activeTabId/splitTabId/device` 的旧单窗口结构须由固定的新接口替换，不能给旧 `splitTabId` 套一层窗口外观。移除 `view-label`、`viewport-stage` 点阵/内边距、平板外壳与全局 device form。

## 10. 诊断、自动化与验收边界

正常 Viewer 不挂 `ReceiveSettings`、`MarkerTools`、`StatsOverlay`，不从 URL/存储中的旧实验偏好静默继承质量参数。独立诊断入口由部署/开发方式提供，可在设置底部放低强调的“连接诊断”链接，但不放正常工具栏；打开独立页，避免诊断挤压远程内容。自动化专页由配置驱动，无交互旋钮；GPU/延迟 profiler 保持正式工程能力。

UI 实施后做必要功能与视觉检查：单窗口贴边、双窗口独立标签/地址/焦点、新窗口创建成功/失败、窄屏窗口切换、站点 UA 应用/取消刷新、设置保存失败、用户退出和隔离、重连与休眠恢复。检查 Chrome 89 和当前 Chromium 的实际外壳布局、键盘/触控可用性。检查真实内容容器尺寸与输入坐标随窗口变化一致，特别是分隔拖动、DPR 变化和触屏键盘。

本设计不安排重复性能验收。性能目标已有主任务结果；UI 验证不应重启已被用户取消的重复实验。
