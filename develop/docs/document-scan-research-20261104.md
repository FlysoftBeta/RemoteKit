# 文档扫描的几何证据与保色增强调查

2026-11-04。结论是保留“照片”和“文档扫描”两个入口。每次扫描先选择可验证的几何处理，再对结果做保色光照与文字对比增强。完整页透视、部分画面的方向校正、保留原几何是同一流程的三种内部结果。部分入镜、白纸白桌和书页都应能得到扫描图。可见像素优先于自动裁齐。

## 当前实现与更改落点

- `endpoint/src/photo_processing.cpp` 的 `ProcessPhoto` 目前无论模式都先识别四边并透视。自动检测使用长边 800 的图、Canny/闭运算及 Otsu 轮廓，要求候选面积占 16–94%、角离画框至少 5 px，四条边各至少 11/19 个采样具有 14 级亮度差。缺失四边或竞争候选重叠不足抛 `no-document`。随后扫描色调把 RGB 全转灰，局部亮度比达到 0.95 后一律饱和白，弱铅笔字和浅色标记有结构性损失。
- `endpoint/tests/photo_processing_tests.cpp` 仅覆盖清楚完整四边、有效手动四点及校正拒绝。本地照片库 UI 捕获 `no_document` 后提示整页入镜；客户端无四角编辑入口。正式文件库契约仍将扫描定义为总做透视。改动时同步校正这些行为与文案，原图继续由现有不可变资产链保留。旧的 `rectify` wire 值是否按客户端兼容保留由 root 决定，不再呈现为独立功能。
- Endpoint 已静态链接 OpenCV 4.11.0 的 `core,imgproc`，解码、EXIF 方向、JPEG 输出由 WIC 实现。现有 4 Mi 像素/8192 最大边、worker 及取消边界可以复用。客户端不做新增图像推理或重采样。Chrome89 主要验证现有资产预览和扫描模式接线。

## 几何建议

1. 优先使用有效的明确四点或完整页高置信四边，记录 `perspective`。自动四边需四段来自画面实证，边框本身不能算纸边，不能把内框、表格、暗影、相邻页或相册照片的矩形当作页边。复用凸性、边长、逐边支撑和重叠歧义筛选。后续若降低现有覆盖面积和对比阈值，必须先证明小页、白桌和密集表格上的误裁率可控。输出四边附近宜保留小安全余量，检测阈值不确定即降级。现有输出宽高取相对边长最大值，只是透视后的比例估计，不承诺原纸尺寸。
2. 截断边只在有足够证据时校正。两条几乎平行的可靠物理边或多个区域的正文基线可估计一个旋转角，走 `deskew`。一条斜边不能区分纸张方向、透视和背景。两组独立平行线的消失点可以提供仿射校正线索，还缺少可靠度量比例与页面范围。可作为后续研究，只有两个独立方向、稳定残差及完整可见帧变换都成立才考虑使用；第一版不估计第四边，不以框外交点作裁剪。弯书页每区基线差异明显时保留几何，不用全局变换把多页拉成一张。
3. Deskew 可用轻量投影。长边 512 灰度图做 9×9 black-hat，取高于 `max(6, 0.65 × P90)` 的内部检测像素。连通组件至少 5 px，宽 2–35、高 3–24 px。按组件质心在 ±15°、步长 0.5° 投影成 2 px 行桶，平滑后用平方和评分。初始门限为至少 35 个组件覆盖每个横向子区、全图相对 2° 以外竞争峰 ≥1.18、两子区各 ≥1.10、全图与各子区角差 ≤1.5°，仅接受 1–13°。生产前加空间覆盖、至少三条分离行、竖排或混合方向反证及两个区域的图案误触检查。对齐且偏角小于 1°，或稀字、混排、过强透视、歧义，都走 `unchanged`。带可靠 90° 旋转证据需另行验收；保留既有 EXIF 方向。
4. Deskew 扩张输出到包含四个变换后的输入画框角，统一缩放服从既有像素预算，不能裁掉边缘字。只填充输入画框外新出现的像素，不能复制字迹。计算矫正后有效像素掩码或在旋转前估计照明，避免新填充污染纸面统计；画框外使用邻近纸色或中性填充。小角度输出可有留白。若预算迫使原图采样率损失过大，则降级保留几何。输出或内部诊断以 `perspective / deskew / unchanged` 和拒绝原因追踪，不记录照片或文字。I/O、取消及显式无效四点仍是真错误；缺少几何证据是扫描成功的正常路径。

## 色调建议

从现有低分辨率纸面估计开始。Bako 等和 Wang/Chuang 的本地/全局背景估计利用深字浅底的假设，只适合作为置信度来源。原形小实验采用长边 512、闭运算尺寸为短边约 10% 且限制奇数 7–25，按 `max(1,k/8)` 做窄 Gaussian，再双线性恢复；全局亮纸参照为背景估计 P85、限制至 96–242。按像素用 `ref / max(B,64)` 求增益，限制到 0.94–1.75；背景亮度 55–105 渐进启用，三个 BGR 通道共用增益。保留高光余量，近纸色细节不会像现算法被统一剪白。处理彩色印章、标记和图片时应对预测通道剪切做软限制，避免偏色。纸面无可信度时减少校光，留住深色桌面、书脊、照片块和热敏纸真实变色。

原形在平滑阴影和硬阴影内部提高了弱字局部亮度差，硬影边界和大暗色图块边缘仍有光晕。首版需测试限制这两类区域的增益。可对大尺度亮度突变使用较窄、分边的估计或把校光混合量降下来，对高彩度连续区域和厚大无文字区域限制高增益；不要把所有暗色解释为阴影。硬影边仍可保留少量亮度台阶。对低对比字的进一步增强可以在可信纸域采用连续、弱局部对比曲线，起始斜率 1.10–1.20，亮纸附近保留斜率，不设硬黑白点。优先以现有校光带来的对比改善为基线，仅在客观低对比样例仍不足时加入额外曲线。全幅 CLAHE 或自适应阈值易放大噪声、改变纸色或去掉弱字。去噪只在可验证的平坦区域小幅降低孤立噪声，细线、条码、标记保留原采样。

生产可用行循环计算并原位更新 BGR。背景图一个 8 位平面最多 4 MiB，灰度转完可提前释放，小工作图不超过 512²。几何阶段保持输入与输出 BGR 峰值约 24 MiB，两阶段不持有多个全幅浮点色图。实际 worker 端峰值仍应加上 WIC、编码与暂存并测量。按照现有队列/租户门禁，长行循环按固定行块检查取消。先以 4 Mi 像素 C++ release 路径单任务 p95 250 ms（含 WIC）为工程调查门限，并测两个连续请求的峰值与取消，不把 Python 数据当作生产承诺。

## 有界实验

`develop/tmp/document-scan-research-20261104/` 存放探针、原图、结果与本地依赖。实际 depot_tools Python、OpenCV wheel 4.11.0.86、NumPy 2.4.6，单 OpenCV 线程、关闭 OpenCL。两张 1600×1200 固定 seed 图包含边缘文字、弱笔迹、彩字和暗色图块。平滑光场和硬台阶分别测试；两张均为画面填满的部分页面。两张公开实拍固定为 Ben White 的弯书照片和 Tijmen Stam 的热敏收据照片。前者文字原图本来失焦，后者边界外有深背景和纸面真实热变色，适于看误变更。两张无对应真值，仅作目视样本。遗留扫描仅复刻色调，绕过几何错误来隔离对比。其模拟结果不代表当前生产可扫描这些图。

| 样本 | 指标 | 原图 | 旧色调复刻 | 有界保色 |
| --- | --- | ---: | ---: | ---: |
| 平滑光 | 纸面 P90–P10 | 84 | 0 | 7 |
| 平滑光 | 弱笔迹局部差 ≥4 的像素占比 | 91.83% | 14.93% | 94.06% |
| 硬影 | 纸面 P90–P10 | 86 | 0 | 7 |
| 硬影 | 弱笔迹局部差 ≥4 的像素占比 | 91.81% | 18.82% | 93.81% |
| 硬影 | 全画面灰度 ≥253 | 0% | 91.01% | 0.66% |
| 弯书 | 全画面灰度 ≥253 | 12.06% | 60.61% | 1.85% |
| 收据 | 全画面灰度 ≤2 | 22.29% | 55.86% | 22.29% |

局部差由 5×5 灰度闭运算近似邻近纸面，在已知弱笔迹掩码上取统计，包含少量阴影边界噪声。目视有界保色保留蓝字、暗色图块、收据背景与变色，但合成硬影及图块边缘仍有细光晕，弯书的散景和纸边会提亮；旧色调把暗图块中心漂白。保色原形的 Python 色调单次中位数 76–87 ms（1.92 MP），实拍弯书约 132 ms（3.21 MP），排除读写和 warm-up。投影原形接受 4 个合成 ±角，误差 0–0.5°，两张未旋转合成图和两张实拍都保留原几何，约 8–21 ms，未执行实际旋转或输出画框验证。只做四张输入、两种色调与单一方向探针，未调参追求样本通过，模型、实体相机、C++ 和并发指标均留给后续验收。

## 验收矩阵

| 输入 | 预期几何与内容检查 |
| --- | --- |
| 对比清楚的完整梯形页，含纸边细字 | `perspective`，检查四角定位、形变、纸边文字和原图可恢复 |
| 截一边/两边，分别含 ±7.5° 横排文字 | 有证据走 `deskew`，误差 ≤1°；所有边缘标记出现在输出，留白容许 |
| 白纸白桌、均匀低对比、空白、反光 | 返回完整视野与保色结果，弱笔迹不消失；无几何证据记 `unchanged` |
| 跨页弯书、互异角度栏目、竖排、色块和无正文背景 | 禁止不可靠全局变换和误裁；照片和印章可区分、色彩可辨 |
| 长收据、票据截头、条码、红章、浅色签名 | 检查上下行、细线与边缘符号，做原图/结果局部对照 |
| 硬影跨字、光照渐变、暗桌与深色图块 | 阴影内部亮度差减小，检查影边 8 px 带的峰谷及大色块边缘；弱字差 ≥4 的像素比例不应下降超 5 个百分点 |
| 过曝/超暗/噪声/真实低质图，歧义四边与非纸矩形 | 无编造内容、色调保守、扫描有结果且无误裁；用户仍可保留原图 |
| 超限图、取消、连续拍摄、两租户、89/157 资产链 | 有界资源和正确错误码；输出 JPEG 预览、持久化、选择以及取消无残留 |

## 主源与模型选择

- [OpenCV 4.11 形态学与滤波](https://docs.opencv.org/4.11.0/d4/d86/group__imgproc__filter.html)、[形状与连通组件](https://docs.opencv.org/4.11.0/d3/dc0/group__imgproc__shape.html)、[仿射与透视](https://docs.opencv.org/4.11.0/da/d54/group__imgproc__transform.html)。这些 API 属于已构建模块。
- [Bako 等，ACCV 2016 论文](https://www.kalyans.org/research/2016/DocumentShadowRemoval_ACCV16.pdf)以局部和全局纸色构建 RGB 影图，提供纸面估计思路。[Wang 与 Chuang，ICASSP 2020 论文](https://dihana.cps.unizar.es/proceedings/ICASSP/2020/pdfs/0001534.pdf)使用局部统计和内在分解。[Jung 等，Water-Filling](https://arxiv.org/abs/1904.09763)估计背景后按阴影区缩放，若硬影是主要剩余失败可单独比较。
- [BEDSR-Net，CVPR 2020](https://openaccess.thecvf.com/content_CVPR_2020/html/Lin_BEDSR-Net_A_Deep_Shadow_Removal_Network_From_a_Single_Document_CVPR_2020_paper.html)和[颜色感知背景网络，CVPR 2023](https://openaccess.thecvf.com/content/CVPR2023/papers/Zhang_Document_Image_Shadow_Removal_Guided_by_Color-Aware_Background_CVPR_2023_paper.pdf)面向更复杂阴影。本轮没有验证可再分发的模型工件、原生 Windows/OpenCV DNN 加载与 CPU 峰值，暂不纳入交付。
- [UVDoc 作者实现](https://github.com/tanguymagne/UVDoc)使用网格形变处理弯曲页，代码仓库 MIT、附 PyTorch checkpoint。[PaddlePaddle UVDoc 模型卡](https://huggingface.co/PaddlePaddle/UVDoc)标 Apache-2.0，[PaddleOCR 模块表](https://www.paddleocr.ai/main/en/version3.x/module_usage/text_image_unwarping.html)列出 30.3 MB 和其 CPU 高性能模式 869.82 ms。这些是不同工件和官方测试条件，未核验本机 ONNX/运行峰值和截断页保真，当前不加运行时或权重。真正书脊展开可以独立立项。
- 实拍来源为 [Ben White，Open book，CC0 1.0](https://en.wikibooks.org/wiki/File:Open_book_(Unsplash).jpg)，原图 SHA-1 `86005395fb88afe2e1bc33e9a24efc30de313f0d`；[Tijmen Stam，Thermal paper，CC BY-SA 2.5 等](https://commons.wikimedia.org/wiki/File:Thermal_paper.jpg)，原图 SHA-1 `07444cc1d250277424b04aeb3f0489cce1d97807`。本地实验输入、衍生图和第三方运行依赖留在 develop/tmp，不进入仓库或测试包。
