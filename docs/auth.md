# 账户、锁屏与人脸验证

## 两层身份

- **账户身份**：注册/登录得到 HttpOnly、`SameSite=Strict` 的 token cookie（HTTPS 时加 Secure），有效期 30 天，查询时不续期。写请求和 WS upgrade 检查 Origin。
- **工作区解锁**：每个新的 Viewer 租约默认锁定。持有有效 cookie 刷新页面不能绕过验证；唯一的例外是刚刚用密码登录或注册时服务端发出的一次性首租约许可（30 秒内消费）。

未登录只能用账号密码。登录后的锁定状态可以用密码、PIN 或人脸解锁。密码始终是恢复手段，修改凭据和锁定策略需要当前密码。

## 锁屏

初始界面和锁定界面是纯白、没有任何控件、进度、错误或交互反馈的空白页。按"上上下下左右左右"才显示登录/解锁表单：可以用方向键，也可以点击或触摸屏幕的对应方向区域（归一化区域判断）。这个序列不授予任何权限，只决定表单是否显示。

**触发锁定**：默认 5 分钟无操作；切到后台默认锁定；可选的 `IdleDetector` 在可用时增加系统空闲/锁屏信号；人脸 presence 模式下检测到用户离开。手动锁定之后要等"离开再回来"或显式验证，避免立即认出仍坐在屏幕前的同一个人而撤销锁定。

## 锁定的执行

锁定必须真正停止产品数据，而不只是本地遮挡：

1. Control 立即停止产品动作和完整状态推送（锁定期间 WS 只推送 auth 与必要的信令），本地状态立即变为锁定。
2. Control 通知 Endpoint 安装新的授权代次（`rtc.authorize{connectionId, epoch, unlocked:false}`）。Endpoint 撤销旧的产品授权：退役排队中的旧输入、产品动作、文件授权；SDK 停止视频与音频 RTP 发送并清空产品媒体。媒体帧在异步编码全程携带接纳时的代次，旧代次的帧不会在解锁后被发出。
3. 客户端本地隐藏画面、音频和弹窗。已经在网络或 SCTP 缓冲里的数据无法收回，所以本地呈现的锁定也是执行的一部分。
4. peer、两条 DataChannel 和接收 track 都保留；认证通道继续可用。

解锁只在 Endpoint ACK 新代次、并重新完成布局屏障与关键帧之后才生效；解锁时 `media.presentation` 带 `restart:true` 重新发布布局，处理 RTC 和 WS 到达顺序不同的情况。

**两个代次**：`AuthState.epoch` 是 Viewer 验证代次（Control 内部的异步工作用它作废迟到的结果）；`peerEpoch` 是 Endpoint 已确认的连接权限代次。产品 DataChannel 消息携带创建时的 `authEpoch`，重试时保留原值；Endpoint 在接收和实际执行时都拒绝旧代次。两者不能混用。管理连接断开时，Endpoint 立即关闭授权，但不重置"最后提交的 unlocked"——相同代次的解锁不能重新打开一个因管理断开而撤销的门，必须更高的代次。

首次登录时曾在 RTC 与授权就绪之前就显示了可操作的工作区，创建操作被误报为"已锁定"。现在 UI 的动作准入要求三者同时满足：产品状态到达、peer 授权已确认、产品 DataChannel 已打开。

## 凭据存储

- 密码与 PIN（6–12 位数字）各自使用 16 字节随机盐、scrypt 64 字节输出；全局 KDF 并发 4；账户尝试默认每分钟 6 次、同时 1 个在途。异步校验完成后、提交之前，重新校验租约与凭据。
- 人脸模板用 AES-256-GCM 加密存储，AAD 为用户 + 模型版本，密钥是 Control 的 32 字节静态密钥文件 `<db>.key`（也用于封装 Tenant DEK，见[多节点](cluster.md#会话放置与密钥)）。客户端从不接收模板；Endpoint 只在挑战期间持有，用完清除。

## 人脸验证

**分工**：Control 发起挑战并裁定授权；Endpoint 负责取帧和推理；客户端只采集。图像不经过 Control，不压缩，不落盘。

**挑战**：绑定 Viewer、connectionId、peer 授权代次、随机 challengeId、用途（enroll / verify / presence）、模型版本和过期时间。enroll 60 秒、verify 30 秒、presence 120 秒；Control 约每 500ms 轮询状态。过期、取消、被替换的结果不能解锁。enroll 要求已解锁且提供当前密码；verify 要求已锁定且有当前模型的模板；presence 要求开启"离开即锁定"。

**传输**：同一 peer 上第二条可靠有序 DataChannel `remotekit-auth`，不加摄像头 RTP track，不建第二个 peer。

```
Client   auth.camera.ready{实际尺寸, RGB24, 最高 5fps}
Endpoint auth.camera.config{同尺寸, RGB24, 5fps, 块大小 16384}
Client   auth.camera.accept
Endpoint auth.camera.frame{captureId}     每次一个许可，间隔 ≥200ms，1 秒内必须完成
Client   二进制块 × N
```

- 摄像头偏好 480×360 前置，最多 640×480 或等面积竖屏，不请求麦克风。客户端读取同尺寸 RGBA、去掉 alpha，不压缩不缩放。480×360 RGB24 5fps 约 20.7Mbps；背压时丢弃这一次采集，而不是堆积视频队列。页面隐藏时不采集。
- 二进制块头 68 字节小端：magic `RKAF`(u32)、version(u16)、头长(u16)、authEpoch(两个 u32)、captureId(u32)、字节偏移(u32)、总字节(u32)、宽高(u16×2)、36 字节 challenge UUID 文本；之后最多 16KiB 像素，像素对齐。
- Endpoint 在分配内存前校验绑定、尺寸和许可，只保留一个组装缓冲和一个最新的待推理帧；格式、代次、挑战变化时撤销未完成的采集。

**推理**（Endpoint，OpenCV 最小模块静态链接）：RGB→BGR → YuNet 单人脸五点检测 → MiniFASNet V1SE + V2 活体 → 对齐后 SFace 128 维归一化特征。

- 检测先保留置信度 ≥0.90 且宽高各 ≥64 的候选框，再要求恰好一个；两个合格人脸仍拒绝。框的每侧最多可越出图像宽/高的 2%，用于活体裁剪和对齐的框钳制到图像内。
- 门限：人脸框边长 ≥64、检测置信度 ≥0.90、两个活体分数各 ≥0.70 且均值 ≥0.90、余弦相似度 ≥0.45。
- MiniFAS 输入 BGR/NCHW float32、原始 0–255、80×80 裁剪（扩展 4.0 / 2.7）、独立 softmax、真人类别索引 1。ONNX 模型由工具从官方权重转换并核对数值。
- enroll 与 verify 在最近 5 个已推理观察帧中，需要 3 个不同帧（按 RGB24 帧 hash）匹配；这 3 帧跨度 ≥400ms，且均位于距当前观察帧 ≤1000ms 的窗口内。未匹配、检测失败或重复帧也占一个观察位置，不清空其他样本。enroll 以当前窗口内第一个有效特征为锚点，3 个样本分别与锚点比较 ≥0.45 后取均值并归一化；锚点离开窗口后才选新的锚点。共享模型推理串行，OpenCV 线程数限制为 2。
- presence：持续有新的匹配帧时保持；5 秒没有新匹配（或没有媒体）判为离开并锁定。

**共享实现**：`endpoint/src/auth/face_engine.{hpp,cpp}` 同时用于 Endpoint 与 `tools/measure/face-eval`，统一模型 hash 校验、RGB→BGR、候选过滤、边界裁剪、活体与特征提取。`face_policy.hpp` 同时用于生产与评测的多帧策略。推理结果包含失败门禁、检测置信度及两个活体分数；生产丢弃分数，仅保留按首个失败门禁累计的计数，`FaceController::Stats()` 返回 `gateFailures`。主 Endpoint stats 尚需在 diagnostics 汇总处接入该方法。
