# 账户、锁屏与人脸验证

## 两层身份

- **账户身份**：首个账户 setup 或登录得到 HttpOnly、`SameSite=Strict` 的 token cookie（HTTPS 时加 Secure），有效期 30 天，查询时不续期。写请求和 WS upgrade 检查 Origin。
- **工作区解锁**：每个新的 Viewer 租约默认锁定。持有有效 cookie 刷新页面不能绕过验证；唯一的例外是刚刚用密码登录或 setup 时服务端发出的一次性首租约许可（30 秒内消费）。

账户由管理员创建（见[控制面 · 账户与管理 App](control-plane.md#账户与管理-app)）；停用的账户 token 立即失效。未登录只能用账号密码。登录后的锁定状态可以用密码、PIN 或人脸解锁。密码始终是恢复手段，修改凭据和锁定策略需要当前密码。

## 锁屏

初始界面和锁定界面是空白页，没有进度、错误或其他控件。在屏幕任意处快速点按三次（相邻两次间隔 ≤500ms、离第一次落点 ≤40px；键盘为连按三次 Enter）才显示登录/解锁表单。这个手势不授予任何权限，只决定表单是否显示。实现在 `control/client/auth/lock-screen.tsx`。

**人脸入口**：账户登记了人脸、且有节点能提供人脸验证时，锁定空白页的中下方显示一个很淡的小人脸图标，不带文字：点按开始识别，识别中显示扫描动画，失败后嘴形变平，再点按重试（状态文字只作无障碍标签）。点按图标本身就是用户手势，满足部分浏览器打开摄像头的要求；点在图标上不计入三击。已有摄像头授权时的自动 verify 也显示为识别中。解锁表单是无卡片的平铺表单，默认用 PIN（未设置 PIN 时只有密码），PIN 与密码用按钮组切换；人脸图标在按钮组上方，尺寸和对比度都高于空白页并带状态文字（正在识别…／未能识别，点按重试），只有识别中与失败可重试两种常见状态——表单由三击打开，打开即开始识别。识别的进行状态由 `face-unlock.tsx` 从 `AuthState.face` 的 verify 挑战推导，空白页和表单共用同一份，关闭表单或页面隐藏时取消显式识别并回到初始状态。

**触发锁定**：默认 5 分钟无操作；切到后台默认锁定；可选的 `IdleDetector` 在可用时增加系统空闲/锁屏信号；人脸 presence 模式下检测到用户离开。手动锁定之后要等"离开再回来"或显式验证，避免立即认出仍坐在屏幕前的同一个人而撤销锁定。

## 锁定的执行

锁定必须真正停止产品数据，而不只是本地遮挡：

1. Control 立即停止产品动作和完整状态推送（锁定期间 WS 只推送 auth 与必要的信令），本地状态立即变为锁定。
2. Control 通知 Endpoint 给两条 peer 安装新的授权代次（Session peer：`rtc.authorize{connectionId, epoch, unlocked:false}`；service peer：`service.authorize`）。Endpoint 撤销旧的授权：退役排队中的旧输入与文件授权；SDK 停止视频与音频 RTP 发送并清空产品媒体。媒体帧在异步编码全程携带接纳时的代次，旧代次的帧不会在解锁后被发出。
3. 客户端本地隐藏画面、音频和弹窗。已经在网络或 SCTP 缓冲里的数据无法收回，所以本地呈现的锁定也是执行的一部分。
4. peer、DataChannel 和接收 track 都保留；service peer 上的认证通道继续可用。

**解锁只靠 Control**：密码与 PIN 在 Control 校验通过即解锁外壳（`shellReady`），不需要任何 Endpoint 在线——Session 所在节点离线时用户照样能登录、解锁、使用开始屏幕、设置、我的文件与学习。peer 的授权随后经期望状态与 `service.authorize` 跟上：之后出现的 peer 被授权时不会重新锁定外壳，授权失败只影响 `browserReady`（远端页面）或文件服务。远端页面在 Endpoint ACK 新代次、并重新完成布局屏障与关键帧之后才恢复交互；解锁时 `media.presentation` 带 `restart:true` 重新发布布局，处理 RTC 和 WS 到达顺序不同的情况。

**代次**：`AuthState.epoch` 是 Viewer 验证代次（Control 内部的异步工作用它作废迟到的结果，产品操作在排队执行时也按它重新准入）；每条 peer 另有 Endpoint 已确认的连接权限代次。DataChannel 消息携带创建时的 `authEpoch`，重试时保留原值；Endpoint 在接收和实际执行时都拒绝旧代次。两者不能混用。管理连接断开时，Endpoint 立即关闭授权，但不重置"最后提交的 unlocked"——相同代次的解锁不能重新打开一个因管理断开而撤销的门，必须更高的代次。

## 凭据存储

- 密码与 PIN（6–12 位数字）各自使用 16 字节随机盐、scrypt 64 字节输出；全局 KDF 并发 4；账户尝试默认每分钟 6 次、同时 1 个在途。异步校验完成后、提交之前，重新校验租约与凭据。
- 人脸模板库用 AES-256-GCM 加密存储，AAD 为用户 + 模型版本，密钥是 Control 的 32 字节静态密钥文件 `<db>.key`（也用于封装 Tenant DEK，见[多节点](cluster.md#会话放置与密钥)）。客户端从不接收模板；Endpoint 只在挑战期间持有，用完清除。

## 凭据恢复

迁移失败或数据库损坏时，先用迁移前自动写出的备份（`backups/`，见[存储与迁移](control-plane.md#存储与迁移)）。备份也不可用、或库停在当前 Control 不接受的 schema 版本时，才用 `recover-credentials` 重建：只保留身份与凭据，其余产品状态一概放弃。发布包里是 `recover-credentials.cmd`（固定使用包内 `config/control.json`），开发时是 `node control/dist/recover-credentials.mjs`（经 `REMOTEKIT_CONTROL_CONFIG` 或默认配置定位数据库）。实现在 `control/server/recovery/`。

```text
recover-credentials.cmd --dry-run      预览：读出哪些账户、放弃什么、为什么
recover-credentials.cmd                停止 Control 后执行
  --from <旧库>  --from-key <key>  --admin <用户名>  --no-tokens
```

- 默认流程：把配置中的数据库及其 `-wal`、`-shm`、`.key`（以及更早版本的 `.face-key`）移到同目录的 `<db>.damaged-<UTC 时间>/`，用当前 schema 新建空库，再写回账户。数据库文件最先移动，Control 仍打开它时 Windows 拒绝重命名，于是什么都不动并提示先停止 Control。写入失败时旧库仍在备份目录，用 `--from` 指向它重试；`--from` 也用于旧库已在别处的情况，此时目标库必须不存在或没有账户。
- 读取：只读旧库的临时副本，不让 SQLite 回写或 checkpoint 原文件。列按旧表实际结构取，不依赖 schema 版本。整表扫描失败时退回逐 rowid 读取，跳过无法解码的行并报告。
- 保留：用户 ID、用户名、Tenant ID、密码哈希、管理员、停用状态、最后登录时间、PIN、人脸模板库、锁定设置中类型正确的字段、未过期的登录 token。用户 ID 不变，所以人脸 AAD 不变；模板库用旧 key 解密并校验后，用新库的 key 重新封装。
- 放弃：哈希不是上面的 scrypt 格式（hex 盐、128 位 hex 输出）的密码或 PIN（密码放弃即放弃该账户），解不开或模板不合法的人脸（同时关闭人脸验证），与已恢复账户 ID、用户名或 Tenant 重复的行。
- 管理员：旧库恰有一个管理员时保留；否则用 `--admin` 指定，未指定则取最早的未停用账户。管理员总是启用状态。
- 放置、checkpoint 与对象索引都不保留，用户下次进入时以新的空 Session 启动；节点上不再被索引的对象由库存对账删除。
- 每个恢复的账户和新建账户一样写入空工作区（`workspaces` 与 `user_settings`）；没有工作区时 Viewer 挂接会失败。

## 人脸验证

**分工**：Control 发起挑战并裁定授权；Endpoint 负责取帧和推理；客户端只采集。图像不经过 Control，不压缩，不落盘。

**不依赖 Session**：模板在 Control，推理只需要节点自带的模型，所以人脸验证（enroll / verify / presence）整个走 Viewer 的 service peer，与 Session 在哪里、是否在运行无关。`FaceController` 由 service peer 持有；模型加载、推理串行与 OpenCV 线程上限按节点共享。推理线程的状态是显式的（未启动 / 运行中 / 已退出）：线程因异常退出时当前挑战以失败结束，下一次挑战开始时先回收它再重新启动，不会出现挑战被接受却无人处理。只要有任何就绪节点就提供人脸选项；一个就绪节点都没有时解锁界面只显示密码与 PIN，并说明原因。

**挑战**：绑定 Viewer、service peer 的 connectionId 与授权代次、随机 challengeId、用途（enroll / verify / presence）、模型版本和过期时间。enroll 60 秒、verify 30 秒、presence 120 秒；Control 约每 500ms 轮询状态。过期、取消、被替换的结果不能解锁。enroll 要求已解锁且提供当前密码；verify 要求已锁定且有当前模型的模板；presence 要求开启"离开即锁定"。

**传输**：service peer 上的可靠有序 DataChannel `remotekit-auth`，与文件通道并列；不加摄像头 RTP track，不为鉴权另建 peer。service peer 换节点或代次变化时，进行中的挑战作废。

```
Client   auth.camera.ready{实际尺寸, RGB24, 最高 5fps}
Endpoint auth.camera.config{同尺寸, RGB24, 5fps, 块大小 16384}
Client   auth.camera.accept
Endpoint auth.camera.frame{captureId}     每次一个许可，间隔 ≥200ms，1 秒内必须完成
Client   二进制块 × N
```

- **自动开启**：锁定后的 verify/presence 与"离开即锁定"的 presence 由客户端自动打开摄像头，不经过用户手势，所以只在不会弹出权限请求时才打开：Permissions API 的 `camera` 为 granted；查询不可用（部分 Safari、WebView 与厂商浏览器）或返回 prompt 时，以 `enumerateDevices` 是否给出带标签的视频输入为准——页面持有摄像头授权时才暴露标签。否则等用户点锁屏上的人脸图标或打开解锁表单时显式开始（显式开始直接请求，允许弹出权限请求）。
- 摄像头偏好 480×360 前置，最多 640×480 或等面积竖屏，不请求麦克风。客户端读取同尺寸 RGBA、去掉 alpha，不压缩不缩放。480×360 RGB24 5fps 约 20.7Mbps；背压时丢弃这一次采集，而不是堆积视频队列。页面隐藏时不采集。
- 二进制块头 68 字节小端：magic `RKAF`(u32)、version(u16)、头长(u16)、authEpoch(两个 u32)、captureId(u32)、字节偏移(u32)、总字节(u32)、宽高(u16×2)、36 字节 challenge UUID 文本；之后最多 16KiB 像素，像素对齐。
- Endpoint 在分配内存前校验绑定、尺寸和许可，只保留一个组装缓冲和一个最新的待推理帧；格式、代次、挑战变化时撤销未完成的采集。

**推理**（Endpoint，OpenCV 最小模块静态链接）：RGB→BGR → YuNet 单人脸五点检测 → MiniFASNet V1SE + V2 活体 → 对齐后 SFace 128 维归一化特征。

- **选脸**：候选框置信度 ≥0.90、宽高各 ≥40。取面积最大者为主脸；第二大的合格候选面积超过主脸一半时判为多人（`multiple_faces`），更小的背景人脸忽略。边界按五个关键点判断（各点距图像边 ≥2px），框本身可以越出画面，裁剪时钳制到图像内。仰拍、离得近时额头或下巴出框很常见，不能因此拒绝。
- **检测重试**：原帧没有合格人脸且整帧偏暗、偏亮、对比过大或大面积截断（亮度均值 <65 或 >190、标准差 >70、近黑/近白像素 >15%）时，对 Lab 的 L 通道做 gamma（目标均值 120）+ CLAHE 后再检测一次；关键点回到原帧上用于活体与对齐。识别输入不做亮度归一化：评测中它没有提高真人接受，LFW FRR 反而略升，而且会让已有模板失去可比性。
- **质量**：由关键点得到眼距、yaw/pitch 代理量，对齐后 112×112 灰度图计算 Laplacian 方差（清晰度）、中心区域亮度均值、对比度、截断比例，以及脸框周围环境与脸的亮度差（背光）。每帧门禁：眼距 ≥18、清晰度 ≥12、脸亮度 15–235、截断像素 ≤65%、亮度 <20 且背光差 >120 判为背光。
- **活体**：MiniFAS 输入保持原帧裁剪，不做亮度校正（防伪拒绝率没有测量数据，不能放宽输入）。单帧两个分数各 ≥0.50 才进入样本窗口；3 帧集合的均值要求各 ≥0.70、两者均值 ≥0.90，即原来的单帧门限改为对集合判定，逆光下偶发低分帧不再直接导致失败。
- MiniFAS 输入 BGR/NCHW float32、原始 0–255、80×80 裁剪（扩展 4.0 / 2.7）、独立 softmax、真人类别索引 1。ONNX 模型由工具从官方权重转换并核对数值。
- **多帧窗口**：最近 5 个观察帧、1000ms 内，取 3 个不同帧（按 RGB24 帧 hash）、跨度 ≥400ms、两两相似度 ≥0.41 的组合作为一个样本，特征取均值并归一化。门禁失败或重复的帧也占一个观察位置。共享模型推理串行，OpenCV 线程数限制为 2。

**模板库**：每个用户 1–5 个录入模板加 0–4 个学习模板，匹配分数取库内最高相似度，门限 0.41。单个模板只覆盖录入那一刻的距离、角度和光线；多模板加上学习，识别率不再取决于某一次录入的质量。

- **录入**：录入期间持续收集通过质量与活体门禁、且与已收集样本中心（medoid）相似度 ≥0.41 的样本，每个样本成为一个模板，取样后清空窗口重新收集。前 3 个模板只需不同于已有模板（相似度 <0.995）或姿态区间（yaw 每 0.15、pitch 每 0.12 一档）是新的；第 4、5 个必须来自新的姿态区间。收满 5 个，或已有 3 个且距第一个满 6 秒时完成。录入中回报进度（模板数/5）和最近约 1 秒的主要阻碍提示：没有人脸、多人、太远、太暗、太亮、背光、模糊，以及样本足够但姿态单一时提示"缓慢转动头部"。录入对话框在预览下方显示进度条和这一行提示；锁屏和解锁表单不显示提示。
- **学习**：verify 成功且该样本对库内最高相似度 <0.60 时，Endpoint 在 `matched` 中附带 `learn`。verify 进行中，若某个样本活体、质量与自身一致性都通过，库内最高相似度落在 [0.335, 0.41)，Endpoint 在 pending 状态中附带当前最好的这种"接近"样本。用户随后在同一挑战期间用 PIN 或密码解锁、且最近一次轮询（≤2 秒）带有 `learn` 时，Control 把它加入模板库：正是"录入时光线好、现在逆光认不出、只好输 PIN"的情形。学习模板满 4 个时替换最旧的；每次解锁最多加一个；presence 不学习；重新录入清空学习模板。0.335 的下限按"任何一个模板库对 LFW 全部图像的误学习率 ≤1e-3"选定，所以已知 PIN 的他人也很难把自己学进库里，何况 PIN 本身已经能解锁。
- presence：持续有新的匹配帧时保持；5 秒没有新匹配（或没有媒体）判为离开并锁定。

**线格式**：verify/presence 的 begin 带 `templates`（1–9 个 128 维归一化向量），enroll 不带；状态回复中 enroll 完成带 `templates`（3–5 个），enroll 进行中带 `progress` 与可选 `hint`，verify 可带 `learn`。两端都严格校验字段、数量和归一化（`endpoint/src/auth/face_wire.hpp`、`control/server/endpoint/face-status.ts`）。Control 侧模板库的加密文档为 v2（`{version, templates: [{source, vector, addedAt}]}`），旧的单向量格式由 schema 迁移 27 转换为一个录入模板；运行时只接受 v2。

**共享实现**：`endpoint/src/auth/face_engine.{hpp,cpp}` 同时用于 Endpoint 与 `tools/measure/face-eval`，统一模型 hash 校验、RGB→BGR、选脸、检测重试、质量、活体与特征提取。`face_policy.hpp` 同时用于生产与评测的多帧、录入与学习策略。推理结果包含失败门禁、质量、检测置信度及两个活体分数；生产丢弃分数，仅保留按首个失败门禁累计的计数，`FaceController::Stats()` 返回 `gateFailures`。主 Endpoint stats 尚需在 diagnostics 汇总处接入该方法。

**评测（FA3，2026-11-20）**：授权私有样本是同一人四次不同场景的手机照片（距离、仰拍角度、顶灯逆光不同，其中一张背景里有另一个人）；只输出数值，元数据在解码前跳过，图像、裁剪、特征向量都不落盘。照片中心裁成 4:3 后缩放到 480×360 与 640×480 模拟摄像头帧。录入用一张照片加逐帧小抖动（±3% 平移缩放、±2° 旋转、噪声）组成 200ms 间隔的序列走真实录入策略；验证对另外三张同样生成序列走真实 verify 策略。四张轮流录入，覆盖全部组合。

| 维度（两种分辨率合计）                                  | 改进前  | FA3     |
| ------------------------------------------------------- | ------- | ------- |
| 原图                                                    | 24/24   | 24/24   |
| 远近（眼距约 60/45/35/28/22px）                         | 78/120  | 120/120 |
| 光照（gamma 0.5/0.7/1.4/2.0、曝光 ×0.5/×1.6、合成逆光） | 162/168 | 162/168 |
| 退化（模糊 σ1/σ2、JPEG q50、噪声 σ6）                   | 96/96   | 96/96   |
| 用暗光（×0.5）录入，验证所有条件                        | 360/408 | 402/408 |
| 用逆光录入                                              | 269/408 | 300/408 |
| 用远距离（眼距 35px）录入                               | 360/408 | 402/408 |
| 用模糊（σ2）录入                                        | 360/408 | 402/408 |
