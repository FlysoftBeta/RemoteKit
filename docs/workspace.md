# 工作区：App、多任务与启动器

工作区是一个 User 的全部产品界面。它由 App 组成：内置的浏览器、我的文件、设置，以及用户把网页安装成的网页 App。屏幕上同时运行多个窗口，交互仿照平板的多任务：一个**窗口组**（Space）放 1–3 个并排的窗口，显示在舞台上；其他窗口组在后台保持完整状态。自动生成的**开始屏幕**既是打开 App、网页和文件的入口，也是切换窗口组的地方。

## 对象

| 对象 | 所有者 | 说明 |
|---|---|---|
| App | Control | `appId`：`browser`、`files`、`settings`、`study`、`questions`、`admin`（仅管理员），或 `web:<id>`（已安装的网页 App） |
| Window | Control | 恰好承载一个 App 的一个实例；`appId`、`lastActiveAt`、App 视图状态 `state` |
| Tab | Control | 仍是远端页面的产品对象，只属于 browser 或 web 窗口 |
| Space | Control | 有序的 `windowIds`（1–3 个）、对应 `weights`、`focusedWindowId`、`lastActiveAt` |
| InstalledApp | Control | 名称、起始 URL、作用域、显示方式、主题色、图标（≤64KiB PNG，存 SQLite） |
| Favorite | Control | 浏览器收藏：URL、标题、创建时间，扁平列表 |
| UsageEvent | Control | 启动器 frecency 的原始记录，见[常用项](#常用项frecency) |

工作区快照 `workspace` 携带 `windows`、`tabs`、`spaces`、`activeSpaceId`、`apps`（已安装）、`favorites`、`settings`、`sites`。每个窗口只属于一个窗口组；窗口组没有窗口就删除；`activeSpaceId` 指向舞台上的组。上限：窗口 16，Tab 32，每组 3 个窗口。

### 窗口种类

- **browser**：标签栏 + 工具栏，即原来的 Window。可以有任意多个 browser 窗口。关闭最后一个 Tab 保留空窗口（显示起始页）。Tab 的 `kind` 只有 `start | remote`。
- **web:&lt;id&gt;**：恰好一个 Tab。紧凑标题栏：图标、页面标题、后退、更多（刷新、复制链接、在浏览器中打开、网站设置、App 设置）。离开作用域的导航留在窗口内，标题栏显示来源域名条；`display=browser` 的 App 始终显示只读地址条。关闭 Tab 即关闭窗口。同一 App 可以开多个窗口。
- **files**：本地渲染，可以开多个窗口；每个窗口有自己的标签页（见[我的文件 · 界面](#界面)）。
- **settings**：本地渲染，单例；再次打开时聚焦已有窗口。
- **study**（学习）、**questions**（题库）：本地渲染，单例；登录时窗口里有一个 Control 拥有的登录 Tab（见[学习与题库](learning.md#登录)）。
- **admin**（管理）：本地渲染，单例，只有管理员能打开（见[控制面 · 账户与管理 App](control-plane.md#账户与管理-app)）。

内置 App 的 appId、标题与单例/本地属性集中在 `shared/product.ts`（`BUILTIN_APP_TITLES`、`isSingletonApp`、`isLocalApp`）。本地窗口（files、settings、admin）不产生远端渲染需求。App 视图状态（files 的标签页及每个文件库标签的视图/搜索、窗口的排列方式，settings 与 admin 的分区）是窗口的 `state`：有界 JSON（≤8KiB），客户端 500ms 去抖后经 WS `window.state` 写回，不走 DataChannel 与操作收据；重连或换设备后原样恢复。地址草稿、滚动位置不持久化。

### 弹窗与新 Tab

- browser 窗口里的弹窗、新 Tab 保持原有收养规则（进入 opener 窗口，new window/popup 产生新的 browser 窗口，放在新窗口组）。
- web 窗口的 `new_popup` 产生同一 App 的新窗口，放在 opener 所在组的右侧（组满则新窗口组）；前台/后台 Tab 和 new window 进入最近使用的 browser 窗口（没有就新建），并切换到它的组。收养仍是同一个真实 WebContents。

## 多任务

屏幕是**舞台**加一个悬浮的**开始按钮**。舞台显示当前窗口组（Space）：1–3 个并排的窗口。切换、新建窗口组和打开 App 都在开始屏幕里完成——开始屏幕同时是启动器和窗口组切换器，所以舞台本身不需要常驻的管理栏。

### 窗口组与可见性

只有当前窗口组的窗口可见；其余窗口 `visible=false`，交给自动回收冻结/丢弃/恢复，状态由 Control 保存，回来时恢复。舞台宽度不足以并排（每窗口最小 360 CSS px）时，一次显示一个窗口，顶部居中的胶囊切换组内窗口；窄屏只改变显示，不改变窗口组结构。上限：窗口 16，每组 3 个。

### 操作

| 操作 | 结果 |
|---|---|
| `window.open{appId, url?, placement}` | `placement` 为 `{mode:'space'}`（新窗口组并切过去）、`{mode:'split', besideWindowId, side}`（插入该窗口左/右侧）或 `{mode:'replace', windowId}`（占据该窗口的位置与比例，被替换的窗口移到自己的新窗口组，不关闭）。settings、admin 已存在时聚焦它 |
| `window.focus{windowId}` | 切到其窗口组并聚焦；更新 `lastActiveAt` |
| `window.place{windowId, placement}` | 移到新窗口组、移到某个窗口旁边（同组为重排，跨组为移入） |
| `window.close{windowId}` | 关闭窗口及其 Tab（beforeunload 流程不变） |
| `space.activate / space.close{spaceId}` | 切换；关闭窗口组即关闭其中所有窗口 |
| `space.layout{spaceId, weights}` | 分隔比例 |
| `app.install / app.update / app.uninstall` | 卸载同时关闭其窗口 |
| `favorite.add / favorite.remove` | 收藏 |

### 舞台

- 窗口铺满舞台，彼此之间只有 1px 分隔线（两侧各有 5px 不可见的抓取区）；并排时聚焦窗口的标题栏顶部有 2px 主色条。分隔线拖动调整比例，拖到距边缘 15% 以内松手，该侧窗口移到自己的新窗口组（不关闭）。
- **窗口把手**：每个窗口标题栏左端的 `=` 把手（两道横线，28×28，指针为 grab）。
  - **点按**打开窗口菜单：移到新窗口组、移到窗口组 ›（按最近使用列出其他组，组满的禁用）、向左移、向右移、关闭窗口。
  - **拖动**（鼠标移动超过 4px；触摸和触控笔按下即可拖）：窗口在原位变暗，缩略显示在指针上方。当前组窗口之间和两端出现插入线，靠近哪条就插到哪里，松手即重排。右侧出现与开始屏幕拖动磁贴时相同的窗口组栏（同一位置、同样的 **+** 与组卡片，放到组卡片即移入该组），末尾多一张**关闭窗口**（松手即关闭，走正常的 beforeunload 流程）。Esc 或在其他地方松手取消。
- **开始按钮**：与键盘开关、退出全屏同一套悬浮按钮（`FloatingActions`，见[移动编辑 · 悬浮按钮](mobile-editing.md#resize-事务)），默认停靠在左下角（底边中点留给文档阅读器的页码与缩放胶囊），可以拖到其他七个槽位。点按打开开始屏幕；舞台因此占满整个高度，不再为外壳留底边。网页或窗口全屏时按钮让位给退出按钮（×）。切换窗口组在开始屏幕的窗口组栏里完成。

## 开始屏幕

全屏覆盖在舞台上（下层模糊变暗）。左上是标题"开始"与搜索框；右上是系统控制：同步状态、声音（左声道、右声道、不播放）、锁定、全屏。

**同步状态**是工作区操作进度的唯一指示：已同步、同步中（带操作数）、等待数据通道、结果未知（警示色，点开可"以当前工作区为准"）。悬停或轻点显示状态说明；只有结果未知时点击会打开面板。舞台和设置项不显示"保存中/同步中"，设置项只显示需要处理的失败或未知结果。主体左侧是按类型分行、一起横向滚动的磁贴；右侧是**窗口组栏**。

### 窗口组栏

- 宽度 ≥ 720 CSS px 时是右侧 200px 的一列，纵向滚动；更窄时是搜索框下方横向滚动的一条。
- 从上到下：**+**（新窗口组）、**当前窗口组**、其他窗口组（按 `lastActiveAt` 倒序）。每张卡片按组内比例排列各窗口的缩略图（离开时保存在客户端内存中的最后一帧，没有就显示 App 图标）和窗口标题。
- 点组卡片：切到该组并关闭开始屏幕。卡片右键/长按菜单：关闭窗口组。
- 点 **+**：开始屏幕不关闭，**+** 变为选中的"目标"，之后点磁贴会在新窗口组中打开，打开后新组成为当前组。再点当前组卡片恢复默认目标。
- **目标**指点磁贴时窗口要加入的组：默认是当前窗口组，用主色描边标出。

### 内容

1. **常用**：App、网页、文件混合，按[常用项](#常用项frecency)得分排序，最多 12 个。
2. **App**：内置 App 在前，已安装的网页 App 按得分排序，全部列出。
3. **网页**：收藏在前（按得分），之后是非收藏的常用网页，最多 16 个。已出现在"常用"里的不重复。

非收藏网页要在至少两条不同的链中出现过，并且至少一次是目的地（非中转），或者它的中转访问最终通向至少两个不同的页面（沿后续中转一直走到停留的页面：聊天首页每次通向新对话，登录页总是通向同一个 App），才进入"常用"和"网页"。只访问过一次的页面，以及登录、人机验证、跳转这类总被穿过到同一处的页面，只是历史记录，仍可搜索。

网页磁贴的标题取该页面各次访问中出现最多的标题（并列取较新的），一次卡在验证页或错误页不会改掉它。
4. **文件**：已整理（在分区中）的在前，之后是其他常用文件，最多 12 个。已出现在"常用"里的不重复。

搜索框输入时，分组换成一个结果组：App、收藏、网页记录、文件按名称/标题/URL 包含匹配；回车打开第一项，没有匹配时按 `resolveNavigation` 在浏览器打开。

激活：

- **点按**：作为新窗口追加到目标组的右侧并关闭开始屏幕。目标是 **+** 或当前没有窗口组时在新窗口组打开；目标组已满时改为在新窗口组打开，并在舞台上短暂提示"当前窗口组已满，已在新窗口组打开"。App 磁贴新建该 App 的窗口（settings、admin 是单例，切到它所在的组）；网页磁贴新建 browser 窗口打开该网页，若某个已安装 App 的作用域覆盖该 URL 则新建该 App 的窗口；文件磁贴新建 files 窗口并预览该文件。窗口数已满时不关闭开始屏幕，提示先关闭一些窗口。
- **拖动**（鼠标移动超过 4px；触摸和触控笔长按 400ms）：磁贴浮起跟随指针，磁贴区域淡出，露出舞台，窗口组栏保持可见。可放置的位置：
  - 当前组的插入线：每个窗口左右两侧各五分之一（48–120px）以及分隔线是插入区，在该处插入（组满时不出现）。
  - 舞台上的某个窗口的中部：替换它（`placement: replace`），被替换的窗口移到自己的新窗口组；悬停时该窗口显示替换高亮和"替换此窗口"字样。组满时整个窗口都是替换区。
  - 窗口组栏的组卡片：追加到该组末尾（组满时显示禁止状态）；**+**：在新窗口组打开。
  - Esc 或在其他地方松手取消，开始屏幕恢复原状。
- **右键 / 键盘菜单**（右键、Shift+F10、上下文菜单键）：添加到当前窗口组、在新窗口组打开；网页和文件磁贴另有"在现有浏览器窗口中打开"/"在现有我的文件窗口中打开"。这是不能拖动时的等价入口。

### 磁贴外观

- **网页**：显示页面预览——Viewer 在网页可见时截取的最后一帧（见下），铺满磁贴，底部渐变遮罩上是标题和域名；背景色取预览的主色。没有预览时用站点主题色（安装过的 App）或按 origin 的固定调色板，显示网站图标。
- **图片文件**：缩略图铺满，背景色取缩略图主色；名称只在悬停或键盘聚焦时出现（触摸设备不显示）。
- **其他文件**：按类型着色，显示类型图标与文件名。
- **App**：内置 App 用固定色（浏览器蓝、我的文件青绿、设置石板灰、学习深橙、题库靛蓝、管理紫），网页 App 用主题色和它的图标。
- 主色：客户端把图片缩到 16×16 求平均色，再在 HSL 中压低亮度保证白字 4.5:1 对比度。

**网页预览**：Viewer 在 Tab 处于可见窗口中、页面加载完成后 2 秒以及离开（切 Tab、切窗口组、导航）时，从该窗口的 video 裁出当前页面，缩到 320×200 以内编码为 JPEG（≤ 24KiB），经 WS `page.preview{url, image}` 交给 Control。Control 按规范化 URL（与 frecency 的 `page:` 键相同）保存到 `page_previews`，每 Tenant 最多 200 条，按更新时间淘汰；`launcher.get` 的网页项带 `previewUrl`（鉴权的 `/api/previews/<hash>`）。"清除浏览记录"与"清除使用记录"同时清除预览。

### 布局

每个分组是一个网格，按可见宽度换行，所有分组上下排列在同一个容器里纵向滚动；分组装不下可见宽度时（例如窄屏上的大磁贴）才横向滚动。磁贴以单元 `u` 为单位：小 1×1、宽 2×1、大 2×2，间隔 8px。

**尺寸**由组内相对常用度决定：`r = s / max(s)`，再用组内名次限制，让同样常用的一组也错落有致（`n` 为组内项数）：

- `n ≥ 3`、`r ≥ 0.6` 且名次在前 `max(1, ⌊n/6⌋)` → 大。
- `r ≥ 0.25` 且名次在前一半 → 宽。
- 其余（含从未使用的）→ 小。

**排布**按优先顺序逐个放入：每个磁贴放进最左边放得下的列，在列内从上到下找位置——第一列优先级最高，前几列的行放满才向右延伸。

**行数与单元**：单元 `u` 只由宽度决定：104 CSS px，并且不超过 `(宽度 − 16) / 3`、不低于 64，让窄屏至少露出约三列。每组的行数是 `⌈面积 / 可见列数⌉`，不设上限、也不为装进可用高度而减行——放不下时开始屏幕纵向滚动；有大磁贴或至少 3 个磁贴时至少 2 行——宽屏平板上宽窄磁贴挤在一行里参差不齐，换到第二行才整齐。只有一行的分组（项数少于 3）全部用小磁贴，同一行里尺寸一致。

- 宽和大磁贴显示标题与副标题（域名、来源）；小磁贴图标与名称居中。

颜色：浏览器蓝、我的文件青绿、设置石板灰；网页 App 用安装时的主题色；网页用匹配 App 的主题色，否则按 origin hash 取固定调色板；文件按类型着色（与 `FileTile` 一致）。磁贴前景统一白色，背景色在 HSL 中把亮度压到保证 4.5:1 对比度。

## 常用项（frecency）

### 记录

`usage_events(tenant, at, item, window_id, chain)`：`item` 为 `app:<appId>`、`page:<规范化 URL>`、`file:<entryId>`。

- App：窗口打开、聚焦（同一窗口 30 秒内的重复聚焦合并）。
- 网页：Tab 主 frame 提交导航（Control 结算导航收据时）。跳过 about:、错误页和搜索引擎结果页（与 `resolveNavigation` 的搜索模板匹配）；标题变化时更新该页最近一条记录的标题（不变不写）。
- **规范化**（`server/url-clean.ts` 的 `cleanUrl`，也用于预览键和收藏）：只记 http(s)，去掉 fragment 与带用户名/密码的 URL；去掉跟踪参数（Brave 的 query filter 与 clean-urls 列表：`utm_*`、`fbclid`、`gclid` 等，以及按站点的 `si`、`igsh` 等）；去掉凭据参数（`code`、`state`、`nonce`、各类 token、`client_secret`、`session`、`sig`、`x-amz-*`、`oauth_*`、Cloudflare 的 `__cf_chl_*`，名字含 token/secret/password/apikey 的参数，以及 JWT 形态的值）；路径含登录/OAuth 段（`/oauth`、`/authorize`、`/callback`、`/signin`、`/login`、`/sso`、`/saml`、`/auth`、`/consent` 等）时整段 query 去掉；剩余参数按名排序，参数顺序不同的同一页面是同一个键。凭据和跟踪参数因此不会写进 usage、预览或收藏。
- 文件：在 files 窗口打开预览、加入文件篮、被网页选择消费；客户端动作经 WS `usage.record{item, windowId}`，服务端校验条目存在。

`chain`：同一窗口（网页再细到同一 Tab）内相邻事件间隔小于 30 分钟属于同一条链；从开始屏幕打开的事件总是开始新链——开始屏幕本身就是用户想绕开的"中转"，不应该被算成路径。停留时间 `dwell` 是到链内下一事件的时间，最长计 10 分钟；链尾的停留按"未知"处理（视为目的地）。

每 Tenant 保留 90 天、最多 20000 条，超出删最旧的。设置提供"清除使用记录"；浏览器设置的"清除浏览记录"只删 `page:` 记录。

### 得分

时间衰减 `w(t) = 2^(−age/7天)`。访问是**中转**当且仅当它在链中有后继且 `dwell < 15s`。

对每个项 `i`：

- 访问量 `f_i = Σ w × (中转 ? 0.3 : 1)`。
- 后继分布 `c(i→j) = Σ_{i 的中转访问，后继为 j} w`，`C_i = Σ_j c(i→j)`。
- 中转率 `p_i = 中转访问权重 / 全部访问权重`，可预测度 `π_i = max_j c(i→j) / C_i`（`C_i = 0` 时为 0）。
- 折扣 `δ_i = 0.8 × f_i × p_i × π_i`，转给 i 最常去的后继 `j*`：直接得分 `D_i = f_i − δ_i + Σ_{k: k* = i} δ_k`。中转的价值在于它通向的地方，所以被扣掉的部分归那里。

用 `D` 排序，取开始屏幕"常用"容量（12）处的分数作为门槛 `τ = max(第 12 项的 D, 0.5 × 最大 D)`（不足 12 项时前者取 0）。

- 枢纽得分 `H_i = (1 − π_i²) × Σ_j c(i→j) × g_j`，其中 `g_j = 1 − min(1, D_j / τ)`。
- 最终 `s_i = D_i + H_i`；收藏网页 ×1.5、已整理文件 ×1.5。

含义：

- `A→B→C`、`A→B→D`：A 几乎总是很快跳到 B，`p_A≈1, π_A≈1`，A 自己只剩约 20%，扣掉的部分转给 B；A 的后继完全可预测，`1 − π_A² ≈ 0`，不会因为"代表 B"拿回枢纽得分。B 不会被重扣（后继分散，`π_B≈0.5`）。
- `B→C`、`B→D`、`B→E`：C/D/E 各自的直接得分低于门槛，`g` 接近 1，它们的访问折算成 B 的枢纽得分——B 作为进入这一簇的入口被抬高。若 C 本身足够常用（`D_C ≥ τ`），C 自己就有磁贴，B 不再因 C 得到加分。
- 只有中转、没有可预测后继的项（例如每次去向不同的门户首页）保留直接得分，并从低频后继那里获得枢纽得分。

计算是纯函数（`server/workspace/frecency.ts`），输入事件列表，输出每项得分；`launcher.get` 时现算（2 万条事件可在毫秒级完成），不缓存派生表。

### 接口

WS `launcher.get` 返回 `{ items: LauncherItem[] }`：每项 `{ key, kind: 'app'|'page'|'file', score, title, subtitle?, appId?, url?, entryId?, favorite?, organized? }`，已按分组规则截断但未分配尺寸；分组与尺寸由客户端纯函数 `launcher-layout.ts` 按视口决定。

## 安装网页为 App

浏览器的更多菜单 → "安装为 App…"。Control 经 Endpoint 调用 Browser 的 `view.appInfo`：返回页面标题、URL、manifest 摘要（name、short_name、start_url、scope、theme_color、display，如有）和一个图标（manifest 图标中不小于 96px 的最佳一个，否则 favicon；Browser 用 `WebContents::DownloadImage` 取回并缩放为 192px PNG，不超过 64KiB）。Control 把图标放进内存表（10 分钟，按随机 `iconToken`），把其余字段作为建议返回给 Viewer。

安装对话框只显示名称与图标；manifest 只提供默认值，不照搬 PWA 行为。"高级选项"展开：起始 URL、作用域（默认起始 URL 所在目录）、显示方式（独立窗口 / 显示地址条）、主题色、以及该 origin 的网站设置（平板版网站、权限——与站点偏好是同一份数据）。确认后 `app.install{…, iconToken}`，Control 把图标写入 `installed_apps`。已安装 App 在设置 → App 中编辑、卸载。

## 设置拆分

- **设置 App**（工作区）：外观（界面缩放、顶部留空、打开时全屏）、画面与声音（质量、声道、统计叠层、音画同步）、输入（聚焦输入框时自动打开键盘）、安全（密码、PIN、人脸、锁屏）、App（已安装网页 App 管理）、会话导入、诊断、公告（全部公告，未读有标记）、账户（退出）、清除使用记录。管理不在设置里，是独立的管理 App。
- **浏览器设置**（浏览器窗口更多 → 设置）：搜索引擎、网站设置列表（所有站点的兼容性选项、权限与协议处理器）、收藏管理、清除浏览记录。
- **我的文件设置**（files 窗口侧栏 → 设置）：来源（排除、清除来源中的文件）、分区管理。

`ProductSettings` 变成 `{ workspace: {...}, browser: { searchEngine } }`，`settings.update` 接受两层的部分更新。我的文件的设置归文件库所有，不在 `ProductSettings` 里。

## 我的文件

我的文件是工作区所有文件的聚合处，有两个用途：**聚合**（自动收集各来源的文件）与**整理**（扁平分区）。

### 模型

- 条目保存 `source: {app, channel} | null`、`partitionId | null`、`collected`、名称、类型、大小；`kind:file` 使用资产，`kind:snippet` 使用 Control 保存的文本与预览。文件选择从请求所属 Tab 的窗口 App 与 origin 推断来源，`browser` 使用页面主机名，`web:<id>` 使用空渠道。「我的文件」的上传和拍照使用 `files/upload` 与 `files/camera`。网页下载完成后由 Control 按 `download/<页面主机>` 收集为未分组条目，来源在界面显示为「下载」。排除该来源后，新下载不入目录。
- 学习 App 自动保存的附件来源为 `{app:'study', channel:<学科名>}`（显示为"学习 › 数学"），条目带 `detail`（作业名或资料名），只用于显示和搜索，不参与分类；超过用户设置的保留天数后按[学习与题库 · 附件进我的文件](learning.md#附件进我的文件)的规则移除。
- 引用：条目存活当且仅当在文件篮中、被未决选择持有、在某个分区中，或 `collected && source ≠ null`。字节仍按 hash 存储，由对象索引引用计数。
- 分区：扁平，`{id, name}`，一个条目最多属于一个分区。
- 来源列表由条目派生：`{app, channel, count, excluded}`；`excluded` 存在文件库的 `excludedSources`。
- 文件篮有一个"发送后整理到"分区（`basketPartitionId`，可为空）。

### 剪贴板

剪贴板位置与全部/最近并列，带计数，窄窗口使用同排 Chip。片段来源固定为 `clipboard/''`，页面或设备出处仅为可搜索元数据。点一行复制，菜单提供全文、移动、删除；全文使用普通比例字体并换行，支持 Viewer 的统一选择手柄。分区和搜索包含片段，全部、最近、开始屏幕和文件选择器只包含文件。

非空文本按用户+hash 去重并移到顶部，未整理保留最新 200 条，分区内保留。设置排除剪贴板停止记录，清除来源删除未整理片段、保留分区内条目。设备同步开关位于设置→输入，默认开启；关闭不影响远端复制和历史收集。存储与消息见[文件与相机](files-and-camera.md#剪贴片段)和[Control](control-plane.md#剪贴板)。

### 规则

- 网页选择确认（`library.finish`）时，被消费的条目：来源未排除则 `collected=true`；设置了 `basketPartitionId` 则同时放入该分区；两者都不满足的条目在选择结束后删除。
- **排除来源**：停止收集该来源的新文件，并把已有文件从"全部"、"最近"和开始屏幕中隐藏；已整理的文件仍在其分区中显示，来源视图里仍可查看并整理。可以取消排除。
- **清除来源中的文件**：该来源的所有条目去掉来源引用；不在分区中的条目删除，已整理的保留（来源显示为"已整理"）。确认对话框写明将删除与保留的数量。被未决选择持有的条目拒绝清除。
- **删除分区**：条目移出分区；没有来源引用的条目随之删除；确认对话框写明数量。
- 方法：`library.partition{id?, name}`（建/改名）、`library.partitionDelete{id}`、`library.move{ids, partitionId}`、`library.source{source, excluded}`、`library.sourcePurge{source}`、`library.basketPartition{partitionId}`，都带操作 ID 与冻结 payload 回执。`groups`/`groupId`/`archived` 删除。

### 界面

files 窗口和浏览器窗口一样有标签栏，二者用同一套组件（`TabStrip` 与 `WindowTab`，`client/app/`）：把手、标签、**+**。标签有两种：

- **文件库标签**（相当于浏览器的新标签页，职责是打开文件）：左侧导航为 全部、最近、剪贴板、分区（带计数，可新建）、来源（按 App 分组，例如 浏览器 › example.com；已排除的置灰），底部是设置；窄窗口改为顶部横向 Chip。内容区沿用按日期分节、卡片/列表视图、搜索与选择模式；整个目录一次给出、不分页，按行虚拟化（列表每项一行，卡片按测得的宽度每行排 N 张），只挂载视口附近的行。来源视图的更多菜单提供排除/取消排除与清除；文件菜单提供移到分区。上传菜单（从设备、拍照）在分区视图中直接上传到该分区，其他视图上传为 files/upload 或 files/camera 来源。标题是当前视图名，图标为文件夹。
- **文档标签**：一个打开的文件（文档、图片、音视频或不支持预览的文件卡片）。从文件库标签打开文件时，该标签就地变成文档标签并记住来时的视图（`from`），工具栏的返回把它变回那个文件库视图——与浏览器新标签页导航到网页一样。工具栏：返回、类型图标、文件名与"来源 › 渠道 · 附带信息 · 大小"（窄于 480px 时只显示名称）、文件篮开关、更多（与文件卡片菜单同一组操作：加入/移出文件篮、移到分区、移出分区、删除；删除后变回文件库标签）。内容区铺满窗口；文件在别处被删除时显示"文件已删除"和关闭按钮。带拍照编辑流程的照片仍在照片对话框里打开。

**+** 新建"全部"文件库标签；关闭最后一个标签时换成新的文件库标签，窗口保留。标签可以拖动重排（只在本窗口内；浏览器标签仍可在浏览器窗口之间移动，二者的拖动分组互不相通），右键或长按菜单有关闭、关闭其他。每窗口最多 16 个标签；只挂载当前标签，文档阅读位置存在 Control，切回来时恢复。窗口状态是 `{tabs, activeTabId, layout, launch?}`，超过 8KiB 时先清掉非当前文件库标签的搜索词。

**打开请求**：开始屏幕的文件磁贴与学习 App 的"在我的文件中查看"向 files 窗口的 state 合并写入 `launch{requestId, entryId?, view?}`；窗口按 requestId 只处理一次并清除它：有 entryId 时在当前标签之后插入文档标签（`from` 为 view 或全部），只有 view 时插入该视图的文件库标签；为这次打开新建的窗口只有这一个标签。条目尚未进入文件库快照时等待它出现。

文件篮的更多菜单（⋯）增加"发送后整理到"子菜单：不整理 / 各分区 / 新建分区。卡片菜单增加"整理到分区"。"从我的文件选择"的网格增加来源/分区筛选。
