# 文件篮与照片卡片交互规格

2026-11-04，按用户最新要求修订：卡片无手柄、整卡拖动；列表有手柄、展开按钮；可手动切换。本文记录交互设计，真实运行和视觉证据见[验收记录](../develop/docs/file-library-qa-20261104.md)。文件篮优先横向卡片条，点击卡片再展开操作。普通文件与照片共用卡片尺寸；普通文件明显居多时默认列表。产品状态、提交确认与 Endpoint 文件契约继续遵循现有实现。

## 模式选择与列表

- 自动模式：当前集合非图片至少3个且占比至少2/3时使用列表，否则使用卡片。根据文件MIME/类型判断图片，缩略图尚未加载或失败不改变类别。空集合初始卡片；未手动切换前随集合类型更新自动判断，但拖动/菜单打开期间不切模式。
- 标题右侧放一个44px图标按钮，卡片时显示列表图标并标注“切换为列表”，列表时反之。手动后该界面实例保持选择，即使增删文件也不自动跳转；不写localStorage、不新增服务端偏好。模式切换保留选择项、操作状态和同ID焦点，切换期间取消未完成拖动。
- 列表每行最低56px：左侧44px手柄（仅可排序集合）、可选Radio、32px缩略图/文件图标、可伸缩文件名及大小、直接展开的操作按钮。无需先点击行才显示操作。窄容器可将按钮区换到下一行，或使用有标签/提示的紧凑图标按钮；“查看”“在后插入”“移除”等与卡片菜单使用同一动作集合，破坏性动作保持独立末项。
- 列表手柄只负责拖动，Radio只负责选择，操作按钮直接可用。图片列表也保留缩略图；列表的完整名称允许两行，卡片继续单行省略。子菜单、确认框沿用原业务语义。
- 我的文件按日期排序的档案集合不能人工重排，因此其列表不显示无效手柄；文件篮与拍照slot列表有手柄。照片审阅默认卡片，仍可通过同一切换按钮查看列表；候选比较固定图片卡片，不提供排序或布局切换。

## 统一卡片

- 白色卡片、1px `divider` 边框、10px圆角；不使用大面积彩色底或默认重阴影。缩略图区浅灰，清晰图像 `object-fit: contain`，完整显示文档边缘。照片同样完整呈现，不为填满框而裁掉内容。
- 紧凑卡片宽144px，预览高108px，文字区高48px；条内间距10px。360px chooser 内部左右16px留白，能看到两张完整卡片及下一张边缘，直接表达横滑。宽屏篮子可用160px宽、120px预览，不随文件名变化宽高。
- 预览左上为小型序号标签，右上为单选控件或状态标签；预览下为单行省略文件名和一行大小/格式。完整名称显示于上下文菜单头与大图页。普通文件在同一预览框内使用40px文件图标及短扩展名，不退回文本列表。
- 卡片不显示手柄；篮子和slot整卡可拖，鼠标cursor为grab，提起后grabbing。普通点击仍打开菜单。集合多于一项时显示轻提示“拖动排序，长按可拖动”；我的文件按日期排序的档案卡片没有重排提示与grab光标。
- 卡片主体是打开菜单与整卡拖动的同一交互区域；Radio为独立兄弟元素，禁止嵌套button。菜单打开仅使用轻描边；真正单选状态使用2px蓝色边框及Radio，二者不能混同。多文件“使用全部”模式没有逐项选择勾选，顺序号不冒充选择状态。
- 缩略图加载显示等尺寸骨架；加载失败保留文件图标及“预览不可用”，文件本身仍可操作。刷新后从Endpoint缩略图读取，不依赖本地拍照Blob才能显示。只在查看大图时读取原文件。

## 文件篮：水平卡片条

- 卡片模式使用`display:flex; overflow-x:auto; overflow-y:hidden; gap:10px`，左右额外4px用于焦点圈；底部8px留细滚动条，不换行。列表模式使用纵向列表。空状态为浅灰圆角区域“还没有文件”，配“添加文件”入口。
- 标题行“文件篮 · N”，右侧保留模式切换按钮与“添加”入口，后者展开设备文件、拍照、我的文件。chooser来源域名单独小字显示，取消与确认固定底部。单选提示“选择一个文件”；多选提示“按当前顺序使用全部 N 个文件”。
- 卡片点击或Enter打开贴卡片的MUI Menu，顶部显示完整文件名与大小，随后按顺序为“查看大图”（仅可预览图像）、“在后面插入…”、“从文件篮移除”。插入项展开/替换为设备文件、拍照、我的文件来源，继承afterId。不展示永久删除。
- 单选Radio只负责选择，不开菜单；点击图片只开菜单，不隐式选择。Radio保留44px触控区域与独立可访问名称。选中后不自动提交。
- 对“我的文件”内的文件篮，直接复用相同双模式组件。容量达到上限时添加/插入禁用，已有文件仍能查看、排序和移除。
- 发送时冻结结构编辑并保留卡片；未知结果继续保留所有文件。仅服务器确认网页选取成功后移除消费项，此处不新增乐观清空。

## 拖拽、横滑与键盘

- 卡片鼠标主键按下后移动超过6px提起，未超过阈值松开即菜单点击。触屏静止长按200ms提起；此前移动超过8px取消长按并交给正常横滑，不能在已经开始横滑后转为拖动。Radio等独立控件排除在整卡drag hit区域外。图片禁止原生dragstart，避免浏览器拖图和自定义排序冲突。
- 卡片触屏待定阶段保留原生滚动，长按提起后才拦截后续touchmove并捕获指针；需要局部非passive touchmove协调，不能认为中途改touch-action就能阻止当前手势滚动。pointercancel必须取消，已被浏览器接管的滚动不得强行恢复拖动。列表只有handle设置`touch-action:none`并可直接提起，其他行区域保持原生纵向滚动。
- 横滑、长按提起及拖动释放后均抑制对应click，不弹菜单；长按不再弹浏览器图片菜单。未提起的短点保持原生菜单点击。禁用阶段及单项集合不启动排序，但正常查看菜单保留。
- 提起时关闭菜单；固定尺寸浮层跟随指针，蓝色描边及轻阴影，原位留同尺寸虚线占位。目标卡片间显示2px蓝色竖线及顶端圆点；越过相邻卡片水平中线更新目标索引。
- 横条左/右边缘36px内自动水平滚动，速度随接近边缘增加，最高约450px/s；列表对应上/下边缘并使用横向插入线。只滚相应容器，不滚Viewer或远端页面。每帧按更新后的卡片矩形重算目标。拖动时关闭scroll-snap；平时可用proximity，不用强制mandatory吸附。
- 顺序变化仅本地预览，放下一次提交完整ID顺序；原位置放下不提交。服务器确认前禁用结构编辑；失败回权威顺序并提示排序未保存。锁定、断线、pointercancel、组件卸载、权威集合变化取消拖动及动画帧。
- 可排序卡片主体获焦点后Enter开菜单、Space提起，左/右箭头移动一项，Home/End到首尾，Enter/Space放下，Escape取消；必须抑制Space生成的button click。列表对应handle获焦点Space提起、上/下移动。保持焦点在同ID并滚入视野；live region播报名称、位置及完成/取消，不使用废弃aria-grabbed。
- 非排序档案卡片Enter/Space都开菜单；列表通过Tab直接访问行内操作按钮。菜单Escape关闭后回原卡。Radio保留原生键盘行为，拖动箭头仅在提起状态生效，互不冲突。

## 拍照统一审阅

- 连续相机仍全屏；完成后只进入一次审阅。审阅上半部为当前大预览（桌面约320px高、移动按可用空间），下半部为相同横向slot卡片条。标题“检查照片 · N”，底部固定“继续拍照”和“加入文件篮（N）/保存到我的文件（N）”。默认不展示逐项重拍/移除/扫描按钮排。
- 点击slot卡片先更新当前大预览并打开该卡菜单；大预览本身点击只进入大图查看。当前审阅slot用细蓝描边/下划线标记，不使用Radio或选中勾，避免误解为只保存这一张。
- slot菜单：“查看大图”“重拍这张”“处理照片…”、“查看候选”（仅确实有不确定候选）、分隔、“移除”。处理子菜单为“原图 / 文档校正 / 扫描”，当前输出用勾标记；选择处理执行原有Endpoint操作。已处理照片可明确切回原图，查看原图不自动更换输出。
- 不确定slot角标“待选片”，总提示“还有 N 张需要选片”；候选确定前保存禁用。普通高置信slot不显示候选入口，不用分数打扰用户。处理中的卡片局部进度，不覆盖其余照片内容。
- 候选比较沿用图片卡片，顶部大图、底部2–3张横向候选；点击候选更新预览与选中标记，底部显式“使用这张”，避免一次点击小图就意外接受。另保留“返回检查”，不默默消除needsChoice。候选无重排handle，因为候选是同一slot的替代图，不是输出文件。
- 重拍仍替换原slot ID/位置；取消保留旧图，成功后只替换该项。审阅slot卡片整卡横向拖动，列表模式使用手柄；不影响候选顺序。移除后当前项选择相邻项，条不跳回开头。

## 我的文件：图片浏览页

- 仍为独立tab。页头两行以内：标题与“文件篮（N）”，主要按钮“添加文件”下拉包含设备上传/拍照；分组选择及“新建分组”置于次行或桌面侧栏。减少当前上传、拍照、新建组、篮子四个并列文本按钮挤占窄窗口。
- 文件按时间降序，标题“今天 / 昨天 / 年月日”；卡片模式下每个日期下面为横排图卡网格，列表模式下为直接展示动作按钮的文件行。模式自动判断基于当前分组的全部可见集合，不按每个日期各自切换。卡片共用缩略图和菜单；网格使用`repeat(auto-fill,minmax(144px,1fr))`，宽屏可限制180px。小于360px内容区可用`minmax(128px,1fr)`保持两列。
- 文件篮卡片模式横向不换行；档案卡片模式使用响应式多行横排网格。日期分段而非每张卡重复长日期；卡片副行保留大小/短格式。已有篮子项角标“已在篮中”，不是勾选框。
- 点击文件卡片才打开菜单：“查看大图”“加入文件篮”（已在篮中禁用并显示状态）、“移动到分组…”、分隔、“删除文件”。删除沿用现有明确确认弹框。菜单头显示全名和完整日期；不常驻移动/加入/删除按钮。
- 从我的文件加入的picker也使用同一图卡网格。卡片点击菜单“加入文件篮”，或picker使用独立选择控件＋底部加入按钮；不能同样点击卡片在这里静默执行、那里却开菜单。建议本批统一菜单加入以减少状态分叉。
- 每次上传有自建分组时仍执行现有分组选择；菜单与卡片只是呈现重整，不改变分组、持久化和删除边界。

## 实现与检查范围

- `file-card.tsx`提供共享卡片，`basket-rows.tsx`提供双模式篮子，`file-view.tsx`管理当前界面的自动/手动视图。卡片只提供整卡drag绑定，不接收/渲染handle；列表才提供handle。业务RPC仍由上层接线。
- `photo-library-capture.tsx`复用卡片外观与横条，保持slot状态机；`my-files.tsx`负责日期分组与图卡网格；chooser只负责紧凑外壳与提交。`sortable-file-items.tsx`使用dnd-kit的鼠标、触屏与键盘sensor，统一拖动预览、边缘滚动、取消与版本校验；当前实现采用2px插入线、单行省略名称以及整体处理忙状态。
- 视觉验收至少覆盖360px chooser多图、普通文件占比触发默认列表、手动切换后不跳回、单文件Radio、我的文件窄/宽布局、slot待选片、长中文名；交互覆盖短横滑不弹菜单、长按整卡跨屏拖动、鼠标整卡拖动、列表handle拖动及展开按钮、键盘重排、菜单与Radio分离、重拍原位、失败恢复、刷新后真实缩略图。截图检查和真实摄像头效果分别记录。
