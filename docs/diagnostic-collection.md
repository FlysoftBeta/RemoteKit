# 用户发起的诊断收集

Viewer 在更多→设置→诊断中点击“开始诊断”，设置关闭，出现悬浮“停止数据收集”按钮。停止后冻结收集、压缩并保存；只有服务端确认文件写入成功才显示“诊断已保存”和可复制的 ID。结果不自动下载到客户端，也不上传第三方服务。

## 保存与查找

Control 默认将诊断文件放在 `control.db` 同级的 `diagnostics/`，可通过 `REMOTEKIT_DIAGNOSTICS_DIR` 覆盖。目录结构为 `<diagnostics>/<SHA256(tenantId)>/<ID>.tar.zst`，旁边的 `<ID>.reason` 保存终止原因以供服务重启后查询。维护人员可按完整 ID 查找文件；文件不位于静态站点目录，不提供匿名访问。

诊断包是标准 tar 经 Zstandard 压缩，使用打包 runtime 自带 Node 的 Zstandard 实现，不依赖客户端压缩能力或额外的命令行程序。包含 `manifest.json` 以及有数据的 `client.jsonl`、`control.jsonl`、`endpoint.jsonl`、`events.jsonl`。

## 数据来源

- Client：浏览器/系统版本、视口与 DPR、可用硬件能力提示、RTC 接收计数及同窗差分、音视频缓冲、组帧和解码、发送端回传统计、呈现与输入时序、布局门禁、DataChannel 状态。复用已有 `getStats()` 采样，诊断不另建 peer 或媒体通道。
- Control：采样接收时刻、进程 CPU/内存与事件循环延迟、质量和音频设置、窗口数量等产品配置。只使用当前租户的有限配置投影。
- Endpoint/Browser：Control 经既有管理连接请求本租户 `session.snapshot(outputDiagnostics=true)`，记录编码器、QSV、Comp Slot/Fence、恢复与 Browser output 状态中可用的技术字段。Endpoint 可以与 Control 分机，不要求访问 Endpoint 本地日志路径。
- Manifest/事件：收集区间、数据来源与记录数、缺测/截断、结束原因、时钟及运行环境。未启用的细粒度 GPU trace、未提供的解码能力或源帧完成时刻均不能冒充已有测量。

客户端约每秒提交一次结构化遥测，经已有授权 WebSocket 归入 Control 诊断会话；这不是设备文件上传或文件篮传输。服务端每两秒独立采样，慢 Endpoint 请求不堆积，也不阻塞停止打包。客户端同一时间最多一个提交，停止后等待已发出的提交终态再请求归档。

计数器是累计值或明确窗口差分；同一诊断包内存在不同机器和时钟域。Client 的 `performance.now()`、浏览器 RTC 报告、Endpoint RTC 报告和 Control 时钟不得直接相减。缓存报告附带采样年龄；缺字段不填零。缓冲和重传的详细口径见[媒体反馈](media-feedback.md)。

## 生命周期与边界

开始和采样绑定当前 Viewer 租约及授权代次；已保存记录归租户所有。锁屏、授权换代、断线和正常服务关闭会结束当前收集并注明原因。客户端保留本页内的诊断 ID，重新连接且解锁后确认原记录状态，不继续给旧收集会话追加数据。重复停止和保存状态查询不会重复生成包。

每次最多十分钟、约 32 MiB 未压缩数据；单条请求最多 128 KiB，限制同时收集数量、数组长度和递归深度。达到上限自动停止，缺样本、超时和截断在结果中标明。归档失败不会显示保存成功。收集中间数据在内存，Control 进程被强制终止或机器断电时不能保证保存；正常关闭会等待归档完成。已完成文件保留在服务端，当前没有自动删除或保留期策略。

仅保存有界技术字段和状态枚举，不打包凭据、SDP、候选 IP、Profile、用户文件、页面内容、输入文本或全局原始日志。这里的完整性指对已接入调试来源的明确覆盖，不能把被排除或未测得的数据解释为正常。
