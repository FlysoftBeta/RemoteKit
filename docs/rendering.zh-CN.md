# Comp / Rend 渲染契约

2026-11-03重构契约。实现、构建和真实运行的进度分别见[当前状态](current-state.zh-CN.md)；本文件不将设计当作已验收结果。

## 所有权与请求

Endpoint的Comp是唯一串流节拍所有者。Browser的Rend托管每个独立Window的离屏合成目标，并把各平面按当前atlas布局合成。Control仍拥有产品visible、窗口与设置，RTC需求不能把产品hidden页面重新显示。

Slot是一个渲染结果及其下游租约的容量单位。请求身份为`(generation, slot, value)`；value从1单调增加，代次、编号和value必须共同匹配。当前资源池最多四个Slot，活动深度可缩小；缩小不取消或抢占已在途租约。

Comp只对可复用Slot发送异步Begin。Rend接受后恰有一个终态：未发生需要保留的GPU写入时发送带原身份的Reject，或者在真实GPU队列上Signal该Slot的ready Fence。成功没有逐帧ready、present或release IPC。各Slot使用独立Fence时间线，其他Slot的较大value不能证明本Slot完成。

共享映射只发布布局与每Slot独立帧记录，seqlock不构成GPU完成证明。Comp必须同时核对请求身份、完整元数据和实际Fence完成后才可把纹理交给编码链。SDK与硬件编码器各自保留的纹理租约都结束后，Endpoint排consumed Fence；实际完成后Slot才能再用于Begin。

独立渲染Mojo message pipe与同步产品控制RPC分开。每Browser/SDK进程对只有一条底层IsolatedConnection；渲染pipe在output.describe成功回复中一次性交付，不能另建第二条会替换Control连接的isolated link。SDK对未完成Begin逐Slot限额；接收Reject或Comp本地报告已观察到Signal只结束请求记账，不越过编码租约。该本地报告不发送IPC。

## 离屏呈现

每个WebContents保持独立Aura root。专用Viz OutputDevice直接把Skia绘制写入共享BGRA目标；不调用FrameSinkVideoCapturer、CopyOutput或屏幕截取API，也不需要本地屏幕Present。Views/Aura及原生输入适配保留。

Browser为每个plane保留有限目标池，最新有效内容引用与合成GPU读租约分别计数。plane目标不能机械地对应atlas Slot：静态plane的最后一帧可能同时被多次atlas合成读取。

Begin携带的目标身份在root绘制任务之前进入GPU队列。Skia提交并结束paint访问后，在ANGLE实际D3D11设备队列上Signal plane Fence。Browser合成队列Wait所需plane Fence，按实际pixel尺寸、DPR与atlas矩形缩放拼接，最后Signal指定atlas Slot的Fence。

同一个root按Chromium的BeginFrame interval规则顺序接纳；不同Slot可同时处于Browser等待、GPU写入、atlas读取和编码阶段。内部调度ACK或“已排Signal”回调都不是实际GPU完成。

Idle Reject要求最后已接受内容已提交，且没有尚未合入atlas的新内容。首帧、布局重建或未就绪目标不能伪装Idle。末帧IDR通过同内容的显式刷新请求取得合法Slot，不能无限持有latest租约堵住深度1。

Idle停止常规Begin；Chromium的实际后续BeginFrame需求通过一次Wake状态事件恢复Comp。Wake绑定最后Idle Reject的完整身份，不是成功帧通知，不释放Slot。仍有rAF等后续渲染需求但本次没有像素更新时不能误报停止驱动。显式刷新及尾IDR可申请force Begin，Stop之后不再唤醒。

## WebRTC与几何

优先高画质、自动、优先流畅分别映射`MAINTAIN_RESOLUTION`、`BALANCED`、`MAINTAIN_FRAMERATE`。这三个选项不再附带不同DPR、像素预算、目标码率或FPS预设。

GCC的`VideoEncoder::SetRates`控制编码码率与帧率；Comp依据该反馈、客户端能力上限及Slot饱和安排Begin。编码器的实际能力和协商H264上限仍须遵守。WebRTC原生source adaptation决定缩放与丢帧，Endpoint只执行其结果并维护布局屏障；旧延迟阈值、DPR因子与独立网络控制器删除。

H264 level的帧尺寸、宏块吞吐率和码率上限属于接收能力约束。宏块吞吐率按最终编码尺寸计算FPS硬上限，同时约束Comp与编码器，不能假定WebRTC或驱动会自动保证；诊断分别显示官方限制与codec限制，不以此新增独立网络缩放策略。

适配只缩放完整atlas，不裁掉任何plane。官方尺寸对齐可能产生X/Y取整差异，布局、ROI、输入和caret转换分别使用对应轴比例。页面DIP和显式Client Scale/DPR不因网络降级而改变。新编码尺寸必须建立新布局屏障，旧在途结果不能披上新布局身份。

Viewer对实际receiver设置`jitterBufferTarget=0`。Chrome89缺少标准属性时使用可用的兼容hint，并明确记录能力；不能把hint或RTP playout-delay扩展描述成标准属性已生效。

## 换代、错误与测量

resize、停止、断链和GPU故障停止接纳旧代请求。旧资源只有在相应读写Fence完成或真实device removal等有效证明下才释放；无法证明的GPU操作保留隔离，不能发普通Reject后立刻复用。

资源换代不要求重建RTC或网页。布局/文档/输入资格仍经过现有代次屏障。Browser进程退出、GPU完成和编码任务结束是不同证明。

Stop/Stopped与Begin/Reject共用有序render通道。Control关闭只停止产品输出，不立即丢弃render pipe；Stop之前的请求全部Reject或已经排Signal后才发送Stopped。Stopped只证明请求终态已确定，未完成GPU工作与编码租约继续保留，超时不得假装排空。

提交时刻不能冒称GPU完成时刻。只有实际Fence完成观察可作为render完成时间；未知时间省略延迟样本。GPU执行、完成观察、编码、网络和呈现分别计量，旧capture路径的历史指标不作为新OSR路径证据。
